- 백업·복구 검사 2개, 문서 링크·브랜드 검사 통과.
- 초기 로컬 브라우저 검사는 5190 포트의 검사 서버 시작 제한 60초를 넘겨 시작하지 못했습니다. 별도 포트 5192의 격리 서버는 진단 시 약 6초 만에 시작했습니다. 최초 지연의 원인은 확정하지 않았습니다.
- 다음 5193 검사에서 Chromium 일부는 `spawn EPERM` 또는 `browserContext.newPage: Target crashed`로 실패했습니다. 앱 검증 성공으로 세지 않습니다. 재실행 및 독립 CI 결과를 아래에 추가합니다.
- 해당 로컬 선별 검사 결과는 24개 중 15개 통과·9개 실패입니다. WebKit 12개는 모두 통과했고 70개 설명의 렌더링, 여섯 화면 폭·양 테마·axe·키보드·확대·명시적 차트 전환을 포함합니다. Chromium은 3개 통과·9개 브라우저 실행/페이지 생성 실패입니다.
- 개인 원문·인증 정보·브라우저 개인 저장소를 공개 증거에 포함하지 않습니다.
- 첫 PR CI `36374185165`에서는 단위 466개·복구 2개를 통과했지만, 브라우저는 85개 통과·1개 실패·개인 경로 2개 제외였습니다. Linux WebKit의 200% 확대에서 고정된 목차 열 때문에 본문과 선택 도구가 좁아져 가로 넘침이 발생했으며, 재시도에서도 같은 검사가 실패했습니다. 화면 너비 대신 실제 읽기 영역에 맞춰 재배치하는 컨테이너 기준 반응형을 적용하고, 넓은 데스크톱 안의 320px 읽기 영역에서 세 종류 설명과 펼친 적용 도구를 검사하도록 추가했습니다. 검사 기준은 완화하지 않았습니다.
