- 타입·단위 검사: 52개 파일, 466개 검사 통과. 사전 70개에 방법·예시·해석이 존재하는지 검사하고, 밴드·VWAP·파워로·계절성 숫자 예시를 실제 계산과 대조했습니다.
- 백업·복구 검사 2개, 문서 링크·브랜드 검사 통과.
- 초기 로컬 브라우저 검사는 5190 포트의 검사 서버 시작 제한 60초를 넘겨 시작하지 못했습니다. 별도 포트 5192의 격리 서버는 진단 시 약 6초 만에 시작했습니다. 최초 지연의 원인은 확정하지 않았습니다.
- 다음 5193 검사에서 Chromium 일부는 `spawn EPERM` 또는 `browserContext.newPage: Target crashed`로 실패했습니다. 앱 검증 성공으로 세지 않습니다. 재실행 및 독립 CI 결과를 아래에 추가합니다.
- 해당 로컬 선별 검사 결과는 24개 중 15개 통과·9개 실패입니다. WebKit 12개는 모두 통과했고 70개 설명의 렌더링, 여섯 화면 폭·양 테마·axe·키보드·확대·명시적 차트 전환을 포함합니다. Chromium은 3개 통과·9개 브라우저 실행/페이지 생성 실패입니다.
- 개인 원문·인증 정보·브라우저 개인 저장소를 공개 증거에 포함하지 않습니다.
- 첫 PR CI `36374185165`에서는 단위 466개·복구 2개를 통과했지만, 브라우저는 85개 통과·1개 실패·개인 경로 2개 제외였습니다. Linux WebKit의 200% 확대에서 고정된 목차 열 때문에 본문과 선택 도구가 좁아져 가로 넘침이 발생했으며, 재시도에서도 같은 검사가 실패했습니다. 화면 너비 대신 실제 읽기 영역에 맞춰 재배치하는 컨테이너 기준 반응형을 적용하고, 넓은 데스크톱 안의 320px 읽기 영역에서 세 종류 설명과 펼친 적용 도구를 검사하도록 추가했습니다. 검사 기준은 완화하지 않았습니다.
- 두 번째 PR CI `36375228983`에서 확대·컨테이너 검사는 통과했고, Chromium의 관련 설명 이동 후 초점 검사 한 건이 실패했습니다(브라우저 87개 통과·1개 실패·2개 제외). 글 제목에 둔 초점을 공통 페이지 전환의 다음 프레임이 본문 영역으로 옮기던 충돌을 수정했습니다. 공통 전환도 설명의 제목을 목적지로 사용하며, 키보드로 관련 글을 열고 뒤로 간 뒤 두 프레임이 지난 최종 초점을 확인합니다.
- 세 번째 PR CI `36376250703`은 앞선 수정과 적용 도구 유지 검사를 통과했으나, 새로 강화한 뒤로 가기 검사에서 실패했습니다(89개 통과·1개 실패·2개 제외). `#example`이 남은 이전 URL에서도 제목 초점을 요구한 것이 원인이었습니다. 뒤로 가기는 읽던 단락으로 복귀하도록 기준을 바로잡았으며, 브라우저 기본 동작에만 맡기지 않고 앱에서도 저장된 단락으로 스크롤·초점을 명시적으로 맞춥니다. 단락 URL·초점·화면 안 위치를 함께 검사합니다.

- 뒤로 가기 검사 기준을 고친 뒤 로컬 WebKit에서 단락의 초점은 맞지만 브라우저의 기본 스크롤 복원이 나중에 화면을 옮기는 현상을 재현했습니다. 즉시 복원과 일시적 수동 스크롤 설정은 각각 4개 중 2개를 실패했습니다. 다음 화면 프레임에서 단락과 초점을 함께 복원하도록 수정한 뒤, 두 관련 흐름을 각각 두 번 검사해 4개 모두 통과했습니다. 저장된 단락이 실제 화면 안에 있는지도 확인합니다.
