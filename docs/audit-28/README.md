# 0.28 이력 시작·위치 밴드 검증

## 발견 및 수정

DOGE 위치 밴드가 약 3년만 표시되던 원인은 두 가지였습니다. 시장에서 선택한 업비트 원화가 새 위치 밴드에도 이어졌고, 주 가격선도 밴드 계산이 가능한 날짜 이후로 잘렸습니다. 압축 보관 이력을 포함한 실제 저장에는 USD 2014-01-23, Binance USDT 2019-07-05, Upbit KRW 2021-02-24 이후의 일별 관측이 있었습니다.

새 위치 밴드는 가장 오래된 검증 원천 하나를 기본으로 선택하고, 주 가격선은 해당 원천의 전체 이력으로 표시합니다. 730일 조건·결측 초기화·미래 관측 미사용·표준편차 0의 위치 null을 유지합니다. 명시된 URL·저장 설정의 원천과 날짜는 바꾸지 않습니다.

## 범위와 증거

- [코인별 시작·밴드 시작 목록](history-starts.csv): 150개 자산, 원천별 가격 시작과 최초 계산 가능 날짜. 출시일 또는 전 세계 최초 거래일로 표현하지 않습니다.
- [원천 시작·첫 가격 검증](provider-origins.json): 241개 거래소 조합과 143개 USD 참조 조합. Upbit는 저장 시작 이전의 캔들이 없는지와 첫 캔들을 확인하고, Binance는 startTime=0, Coin Metrics는 공식 일별 카탈로그 최소 시각과 실제 첫 응답으로 확인합니다.
- [온체인 시작 대조](network-origins.json): 34개 자산·442개 저장 조합. 408개 노출 지표와 34개 내부 참조가격을 포함합니다. 유도값의 시작은 필요한 원천 필드 시작일 중 최댓값과 대조합니다. 전체 과거 관측값 검산은 포함하지 않습니다.
- [DOGE 페이지 검증](doge-before.json): 전체 페이지 5/3/3, 각각 USD 4,643개·Upbit 2,055개·Binance 2,655개 응답. 진행 봉을 포함하는 API 응답 개수이며 계산은 확정 봉만 사용합니다.

앞선 0.27 감사 도구는 `candles`의 최근 행만 집계해 보관 이력의 시작을 누락했습니다. 해당 시점의 과거 감사 파일은 보존하고, 새 도구에서 `price_archive`와 최근 봉을 합쳐 중복을 제거합니다. 정상 응답이나 최근 500개만으로 전체 이력 확보를 판단하지 않습니다.

## 검증·배포 상태

이번 이력 표시 변경은 원격 CI·main 병합과 양 주소 배포·공개 차트 검증을 마쳤습니다. 전체 운영 정상과는 별도로 판단합니다. 기존 개인 자료·사용자 문서·저장 키·이력 DB를 보존하며 48시간 대기는 적용하지 않습니다.

VPS API `vps-3619f378788bf685`와 [Pages 배포](https://965c4cea.coin-desk.pages.dev)를 반영했습니다. API 외 6개 컨테이너 ID, 수집기·예약 정책·스키마 0009는 유지했습니다. 같은 Docker 빌드의 공개 파일 250개씩을 양 주소에서 대조했습니다. VPS HTML의 공유 이미지 주소 두 곳만 해당 배포 주소로 바뀌며 나머지 바이트는 일치합니다. main의 소스 505개도 릴리스 manifest와 일치했습니다. [배포 파일](deployment-assets.json) · [소스 대조](source-match.json) · [API 전환](activation.json)

양 공개 주소의 실제 데이터로 DOGE MVRV에서 위치 밴드로 이동, USD 최초 가격 2014-01-23·밴드 2016-01-23, 초기 가격 날짜 고정, 원화 링크 2021-02-24 유지, 양 테마 axe 0·CSP 위반 0·페이지 오류 0을 확인했습니다. PC 차트 시작 226px·높이 440px, 모바일 최초 시작 261px입니다. 날짜를 고정하면 297px이므로 이 상태에서는 종전 280px 배치 목표를 충족하지 않습니다. [공개 사용 흐름](production-user-flow.json)

## 운영 관측과 한계

120초 읽기 전용 표본에서 핵심 시세 6개의 실제 체결·확인 시각이 증가했고 네 수집 lane의 진행을 확인했습니다. 선물 확인 증가는 6개여서 기존 9개 표본 기준은 통과하지 않았으며 `naturalSampleVerified=false`를 유지했습니다. 진행 중인 시세 작업도 COUNT에 포함되므로 `recordedRuns`와 성공 횟수를 구분했습니다. 이후 읽기 조회의 최근 시세 작업 6회는 모두 ok였습니다. 다른 방문자 부재나 하루 전체 정상의 증거는 아닙니다. [자연 갱신 표본](natural-cron.json) · [후속 예약 조회](operating-attention.json)

프로세스·DB health는 정상이지만 전체 원천 health는 일부 실제 체결·시간봉 지연을 포함해 HTTP 503입니다. 현재 지연을 이력 표시 수정으로 해결했다고 표현하지 않으며 300초 실제 체결 조건과 기존 신선도 기준을 유지합니다. 원천이 제공하지 않는 출시 초기 구간, 시간봉 90일 정책, 계약별 선물 이력의 범위는 그대로입니다. 실제 Safari·VoiceOver와 사람 대상 사용성 검사는 미검증입니다. 48시간 대기는 다시 넣지 않았습니다.

초기 로컬 fixture 기동 실패, 파일 검증 도구의 UTF-8/cp949 오류, Pages의 SPA 경로를 JSON API로 읽었던 오류는 [검증 기록](verification.json)에 구분했습니다. 공개 운영 오류의 원인으로 소급하지 않습니다.
