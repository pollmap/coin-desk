## 2. CRITICAL 두 항목의 적용 조건

### CVE-2025-7458 · libsqlite3-0

보고서의 설치 버전은 `3.40.1-2+deb12u2`입니다. [Debian 공식 tracker](https://security-tracker.debian.org/tracker/CVE-2025-7458)는 bookworm을 취약 상태로 기록하고, 이 문제의 공격 조건을 공격자가 임의 SQL을 실행할 수 있는 경우로 설명합니다. 복잡한 SELECT·ORDER BY 식에 따른 정수 overflow가 서비스 거부나 메모리 정보 노출로 이어질 수 있습니다. Debian의 제한된 우선순위 표기를 취약점 해결이나 위험 없음으로 해석하지 않습니다.

보리차트의 점검한 공개 읽기 경로는 서버가 정한 SQL에 값을 바인딩합니다. 자산·지표·원천을 카탈로그로 제한하고 날짜·페이지·조회 개수를 검사합니다. 검색 문자열도 매개변수로 전달하며 공개 API에서 SQL 문장 자체를 입력하는 인터페이스는 확인되지 않았습니다. 이번 운영 조회 역시 정해진 SELECT만 수행하고 `query_only`·5초 진행 deadline·400행 상한을 사용했습니다. 공격용 SQL은 실행하지 않았습니다.

이는 공개 입력이 해당 공격 조건에 도달하는 경로를 줄이는 근거입니다. **설치된 취약 라이브러리가 고쳐졌다는 근거는 아닙니다.** 특히 Node에 포함된 SQLite와 Python·OS의 libsqlite3은 별도로 확인해야 하며 한 런타임의 버전으로 이미지 전체를 정상 판정하지 않습니다. DB·백업·이관 파일을 임의의 사용자 SQL 실행 경로로 공개하지 않는 조건을 유지합니다. SQLite의 [공식 보고·수정 논의](https://sqlite.org/forum/forumpost/16ce2bb7a639e29b)도 별도 참고 자료입니다.

### CVE-2023-45853 · zlib1g

보고서의 설치 버전은 `1:1.2.13.dfsg-1`입니다. [Debian 공식 tracker](https://security-tracker.debian.org/tracker/CVE-2023-45853)는 이 문제가 MiniZip의 ZIP 작성 처리에 관한 것이며 bookworm의 해당 zlib 소스에서는 `contrib/minizip`을 바이너리로 만들지 않아 해당 항목을 제외하는 이유를 기록합니다. 독립 minizip 패키지와 zlib 소스 항목도 구분합니다.

따라서 스캐너의 zlib1g CRITICAL 이름만으로 보리차트의 gzip·SSE·차트 처리가 같은 공격 조건에 있다고 단정하지 않습니다. 동시에 이 배포판 설명을 모든 ZIP 처리기나 별도 번들 MiniZip의 안전성으로 확대하지 않습니다. 별도의 MiniZip·pyminizip·제3자 압축 패키지가 들어가는 경우에는 다시 확인해야 합니다. 이 검토에서 컨테이너 실행이나 공격 파일 생성은 하지 않았습니다.

## 3. 현재 보존하는 경계

- 공개 API의 허용 입력·요청 크기·페이지 제한, SQL 값 바인딩을 유지합니다. 오류나 지연을 우회하려고 임의 SQL 실행·인증정보 반환 경로를 추가하지 않습니다.
- 공개 시세 요청은 거래·인증 method를 허용하지 않습니다. 내부 hub 조회는 선택 자산과 private/loopback 주소만 사용합니다.
- 컨테이너의 read-only rootfs, 비특권 UID, capability 제거, no-new-privileges, loopback 포트와 격리된 프로젝트 볼륨을 보존합니다. 운영 DB 쓰기 권한은 정해진 수집·DB 볼륨 안에 유지합니다.
- 원격 준비 도구는 검증된 CI 산출물과 서비스별 image/config를 대조합니다. 원문 inspect·환경 설정과 subprocess 출력은 비공개 감사 경로에만 보관하고 공개 문서·응답에는 넣지 않습니다.
- 운영 데이터 조회·이력 검사와 후보 검증을 실제 서비스 교체와 구분합니다. 이번 읽기 전용 확인이 패키지 패치나 서비스 배포를 수행한 것은 아닙니다.
