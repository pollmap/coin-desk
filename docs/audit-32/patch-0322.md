# 0.32.2 모바일 차트와 버튼 보완

0.32.1 운영 화면의 추가 검수에서 BTC 해시 리본의 모바일 차트 시작점이 303px, DASH 해시레이트 추세가 281px로 확인됐습니다. 목표 280px를 넘은 상태이며, 앞선 가격 화면의 배치 통과를 모든 지표의 배치 통과로 확대하지 않습니다. 두 문제는 0.32.1 이전 운영판에서도 존재했고 주기 설명 수정의 회귀로 판단하지 않습니다.

해시 모드의 수치·단위·기준일·60일 평균 범례가 좁은 화면에서 줄바꿈되며 높이를 늘린 것이 확인됐습니다. 이어서 가격 원천 버튼 24px, 관계 버튼 24px, 날짜 고정 뒤 최근값 버튼 32px도 발견했습니다. 실제 가격을 원천 버튼 안에 묶어 44px로 만들고 가격을 접근 가능한 설명으로 연결합니다. 최근값은 같은 동작과 이름을 가진 44px 아이콘 버튼으로 제공합니다. 수치·단위·확정 관측·계산·날짜 상태·API·수집 규칙은 변경하지 않습니다.

보조 수치를 차트 아래에 한 번만 표시하고, 좁은 화면의 고정 날짜는 짧게 표시하면서 전체 UTC 시각을 스크린리더와 정보에 보존합니다. 실제 intraday 관측은 시각을 함께 표시합니다. 의미 있는 단위와 버튼을 숨기거나 음수 여백·좌표 이동으로 배치 기준을 맞추지 않습니다.

첫 범위 검사에서 작은 버튼이 발견됐고, 후속 32개 검사에서는 18개 통과·14개 실패였습니다. 이때 배치·단위·44px는 통과했지만 `time` 요소의 `aria-label`이 axe 규칙에 맞지 않았습니다. 의미 있는 `time`과 전체 시각의 읽기 전용 텍스트를 유지하는 방식으로 고쳤습니다. 다음 34개 검사에서는 31개 통과·3개 실패였으며 슈퍼트렌드 고정 날짜의 296px 두 건, WebKit 가격의 285px 한 건이 남았습니다. 이 실패를 완료로 합산하지 않고 보조값과 정상 간격 규칙을 추가 수정합니다.

WebKit의 가격 화면은 실제 요소 크기를 대조해 기본 선택창의 고유 높이 때문에 지표 제목 행이 49px로 늘어났음을 확인했습니다. 해당 선택창의 모바일 높이를 44px로 명시했습니다. 슈퍼트렌드 보조값도 같은 단일 범례의 아래 배치를 사용합니다. 계산 검사에서 숫자·조건은 그대로 유지하며 이동한 요소의 선택자만 맞춥니다.

320·390px, 두 테마, BTC 리본·DASH 추세 각각의 배치와 값·단위 표시를 확인하고 PC 440px 차트와 팝업 동작도 검사합니다. 검사·CI·운영 배포 결과는 완료한 증거로 덧붙이며, 0.32.1의 사용 흐름 44개·주기 12개·검색 14개 통과는 이전 릴리스 기록으로 보존합니다.

동결된 최종 소스의 표적 Chromium·WebKit 28개는 재시도 없이 통과했습니다. 390px의 가격·MVRV·슈퍼트렌드는 두 테마·두 엔진 모두 차트 시작점 초기 270px, 고정 280px, 최근값 복귀 270px였으며 가격 정보·최근값 버튼은 44px였습니다. BTC 리본과 DASH 추세의 320·390·1280px 배치, PC 높이, 단위·전체 UTC 날짜·일중 시각 구분·초점 복귀·axe도 통과했습니다. 합성 관측은 실제 원천 신선도나 과거 이력의 완전성을 검증한 결과로 표현하지 않습니다.

이 검사 서버는 Vite의 개발 미들웨어와 격리된 메모리 fixture를 사용합니다. 생산 빌드의 근거로 대신하지 않으며, 이후 같은 동결 소스의 `npm run build`에서 TypeScript와 생산 Vite 빌드를 별도로 통과했습니다. 문서 링크 검사와 diff 공백 검사도 통과했습니다. PR·main 전체 CI와 운영 적용은 후속 게이트입니다.
