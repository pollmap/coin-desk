## 2. 발견 사항과 처리

### 사용자 보고와 확인된 결함을 구분

사용자가 보고한 **가격·MVRV 등 전환 뒤 오른쪽에 새 창이 생기는 동일 증상은 이번 확인에서 재현하지 못했습니다.** 해당 바로가기는 같은 탭의 React Router 링크이며 새 브라우저 창을 여는 처리를 사용하지 않습니다. 일반 지표 선택창은 운영 브라우저 확인에서 중앙으로 열렸습니다. 이 사실만으로 보고된 증상이 없다고 단정하지 않습니다.

다음 결함은 보고된 동일 증상과 별도로 확인·처리했습니다.

| 발견 사항 | 원인·영향 | 처리와 검증 |
|---|---|---|
| Portal 밖에서 모바일 스타일이 빠짐 | `DeskDialog`는 body Portal에 렌더링되지만 일부 지표 선택 스타일은 `.product-desk` 부모를 요구했습니다. 팝업은 해당 부모 밖에 있습니다. | 선택창 스타일을 `.desk-dialog` 내부 컴포넌트 규칙으로 정리했습니다. 실제 Portal의 행 높이·버튼 크기·화면 경계를 검사했습니다. |
| 다른 팝업 위에 검색이 열릴 수 있음 | 글로벌 `/` 단축키가 이미 열린 대화상자를 확인하지 않았습니다. 팝업의 버튼이나 링크에 초점이 있으면 두 층이 열릴 수 있었습니다. | `ProductTopbar`의 단축키와 검색 이벤트에서 열린 dialog를 확인합니다. 지표 선택창의 닫기 버튼에 초점을 둔 채 `/`를 누르는 회귀 검사가 통과했습니다. |
| 관계창 요청이 후속 분석에 따라감 | `knowledge=1`이 URL에 남고 일반 지표·코인 전환에서도 전달되었습니다. 관계창의 일회성 요청과 이후 탐색이 분리되지 않았습니다. | 요청을 소비해 URL에서 제거하고, 지표·코인 전환에서 `knowledge`·`related`를 제거합니다. 팝업 열기도 한 종류만 활성화하도록 정리했습니다. 이 항목의 최종 상태·공유·뒤로 가기 검증은 전체 검사 기록과 함께 확인합니다. |
| 현재 지표 재선택으로 기간이 초기화됨 | 이미 선택한 항목에도 기본값을 만드는 `indicatorUrl`이 적용되어 명시적 기간·확대 구간을 지울 수 있었습니다. | 일반 클릭은 현재 분석을 유지하고 선택창만 닫습니다. Ctrl/Cmd/Shift/Alt 클릭은 브라우저 링크 동작을 유지합니다. 현재 항목 재선택 후 URL·기간 보존 검사가 통과했습니다. |
| 사전 목록마다 150개 티커가 반복됨 | 일반 사전 항목의 기본 지원 명부가 전체 자산으로 확장됐지만 목록 표시도 전체를 이어 붙였습니다. | 목록은 선택 코인의 적용 여부만 표시하고 전체 명단은 필요할 때 펼치도록 바꿨습니다. |
| 선택 자산의 해시레이트 단위가 일반 TH/s로 표시됨 | 일반 지표 정의의 단위를 그대로 표시하면 DASH·ZEC의 GH/s와 맞지 않았습니다. | 공통 단위 해석과 자산별 사전 산식·예시를 사용합니다. GH/s와 10⁹ 표기 회귀 검사가 통과했습니다. |

Portal·검색 중첩·관계 요청의 수정이 **사용자가 보고한 오른쪽 창의 원인을 확정하거나 동일 증상의 해결을 입증한 것은 아닙니다.**

- 작업 중 일부 실행에는 동시 소스 편집에 따른 Vite HMR 로그가 있습니다. 코드 동결 후 전체 실행과 원격 CI가 최종 검증 근거가 되어야 합니다.

타입 검사 `npx tsc -b`와 변경 파일의 `git diff --check`가 통과했습니다. 이것은 전체 운영·보안·사용성 검증 완료를 의미하지 않습니다.
