# 0.32 분석 모형과 검증 기록

작성일: 2026-10-13 KST. 이 문서는 새 계산 모듈과 해당 모듈의 독립 계산·브라우저 검사를 기록합니다. 코드 검사, 합성 관측을 사용한 UI 검사, 실제 원천 표본 확인, 운영 배포 검증은 서로 다른 범위입니다. 최종 배포·전체 회귀 결과는 이 문서의 중간 실행 결과로 대체하지 않습니다.

## 1. 코인별 자체 레인보우

신규 지표 `view:asset_rainbow`는 선택한 코인·원천·통화의 가격만 사용하는 자체 실험 모형입니다. 기존 BTC 제네시스 기준 `view:btc_rainbow`, 앞선 연속 730일 분포를 사용하는 가격 위치 밴드는 각각 유지합니다. 세 계산은 이름이 비슷해도 같은 모형이 아닙니다.

| 항목 | 계약 |
|---|---|
| 계산 모듈 | `shared/asset-rainbow.ts` |
| 모형 버전 | `bori-asset-expanding-log-regression-v1` |
| 고정 기준 원장 | `shared/rainbow-origins.json` · `bori-rainbow-anchor-v1` |
| 원장의 원검증 | `verified-history-start-v1` · 2026-10-11 04:12:28.313966 KST |
| 기준일 | 해당 원천에서 확인한 최초 일별 관측. 코인 출시일이나 전 세계 최초 거래일이 아님 |
| 입력 | 양수·유한값, 고유하고 증가하는 UTC 일별 시각, 기준일 이후, `time + 86400 <= cutoff`인 확정 관측 |
| 표본 | 표시일 이전 유효 관측 최소 730개. 연속 730일이라는 조건과 구별 |
| 좌표 | `x = ln(1 + 기준일 이후 경과일)`, `y = ln(가격)` |
| 회귀 | 과거 누적 표본의 최소제곱 회귀 `y = a + b × x` |
| 분산 | 과거 회귀 잔차의 모집단 분산, `σ = sqrt(Σ잔차² / N)` |
| 구간 | `exp(a + b × x + kσ)`, `k = -2.25, -1.75, …, 2.25`의 10개 경계·9개 구간 |
| 처리량 | 누적 평균·공분산으로 O(n). 현재 표시일 가격은 해당 일의 회귀에 포함하지 않음 |

표시 기간이나 확대 구간으로 원천 이력을 잘라 회귀를 다시 학습하지 않습니다. 전체 확보 이력에서 계산한 결과의 표시 구간만 바꿉니다. 결측은 보간하지 않으며, 중복·역순 시각과 잘못된 관측은 계산 표본에서 제외합니다. 표준편차가 사실상 0이면 위치 점수는 `null`입니다. 가격이나 밴드의 수치 범위를 벗어난 회귀는 숨겨 정상값처럼 표시하지 않고 `assetRainbowDiagnostics`의 `eligibleFits`·`rejectedFits`로 구분합니다.

### 기준일과 관측 변경

v1 기준 원장은 일반 가격 이력 카탈로그에서 분리해 고정했습니다. 일상적인 이력 보완으로 기존 기준일을 자동 이동시키지 않습니다. 원장에 없는 원천은 `origin=null`로 남기며 다른 원천의 기준일을 가져오지 않습니다. 기준일보다 오래된 관측이 추가돼도 기존 버전에서는 그 관측을 제외합니다. 새 기준을 채택할 때는 별도의 명시적 anchor 버전과 변경 기록이 필요합니다.

결과와 저장 설정은 자산·원천·통화·고정 기준일·anchor 버전·모형 버전·관측 변경 식별자를 구분합니다. 화면은 알 수 없는 기준이나 원천·통화 조합을 기존 모형처럼 표시하지 않고, 사용자가 현재 모형으로 다시 여는 행동을 제공합니다.

`dataRevision`의 `obs-v1-…` 값은 받아들인 관측 내용과 모형 맥락에 대한 **결정론적 변경 식별자**입니다. SHA-256이나 암호학적 진위 증명이 아닙니다. 원본 관측의 과거 revision 전체를 보관하는 기능도 아닙니다. 저장 후 원천이 과거 관측을 수정하면 모형 설정을 유지하면서 최신 수정 관측으로 재계산하고 변경 안내를 표시합니다. 따라서 완전한 당시 결과 재현이라고 표현하지 않습니다.

미래 관측만 뒤에 추가하면 과거의 계산 결과는 유지됩니다. 과거 값을 수정하면 그 관측 이후의 회귀가 바뀔 수 있으며, 이는 미래 데이터 참조와 구별되는 정상 재계산입니다.

## 2. BTC 해시 리본과 다른 PoW의 해시레이트 추세

| 항목 | BTC 해시 리본 | 다른 PoW 해시레이트 추세 |
|---|---|---|
| 지표 | `view:hash_ribbons` | `view:hashrate_trend` |
| 버전 | `bori-btc-hash-ribbons-30-60-price-10-20-v1` | `bori-hashrate-trend-30-60-v1` |
| 모듈 | `shared/hash-ribbons.ts` | 같은 모듈의 별도 인터페이스 |
| 입력 | 확정 일별 HashRate와 같은 날짜의 BTC PriceUSD | 해당 네트워크의 확정 일별 HashRate |
| 선 | 해시레이트 SMA30·SMA60 | 해시레이트 SMA30·SMA60 |
| 가격 조건 | 가격 SMA10이 SMA20보다 높음 | 사용하지 않음 |
| 사건 | 감소 교차·회복 교차·회복 후 가격 조건 충족 | 감소 교차·회복 교차 |

해시레이트가 60일 연속 확보된 뒤 표시합니다. 최초의 낮은 평균값만으로 과거의 하향 교차를 만들어내지 않습니다. 두 평균이 같거나 부동소수점 오차 범위에서 같은 경우에는 새로운 교차로 처리하지 않습니다. 회복 이후의 가격 조건 충족은 회복 주기마다 한 번만 표시합니다. 전환 목록은 계산 날짜를 클릭해 해당 날짜를 고정할 수 있게 합니다.

해시레이트 결측·무효값에서는 두 계산창과 주기 상태를 초기화하고 연속 60일을 다시 확보합니다. BTC 가격 입력의 20일 연속 조건이 사라지면 현재 주기의 가격 확인 자격을 취소합니다. 이후 가격을 20일 다시 확보해도 오래된 회복 주기의 확인을 생성하지 않으며, 새 감소→회복 주기가 필요합니다. 가격이 없어도 확보된 해시레이트 두 선 자체를 지우거나 가격을 임의로 채우지 않습니다. 렌더러 역시 결측·계산 준비 구간을 선으로 이어 붙이지 않아야 합니다.

[Capriole 원문](https://capriole.com/hash-ribbons-bitcoin-bottoms)의 해시레이트 평균과 가격 모멘텀 개념을 참고한 보리차트 계산입니다. 원문의 모든 전략 타이밍·데이터 원천·백테스트 결과와 일치한다고 주장하지 않습니다. UI의 사건은 확인한 조건이며, 매수 권고·바닥 확정·수익 보장이 아닙니다.

### 적용 대상과 단위

검토한 자산 명부의 HashRate 지원은 BTC·DOGE·BCH·ETC·ZEC·LTC·DASH 7개입니다. MVRV는 명부상 33개이며 150개 모두의 MVRV 확보 완료를 뜻하지 않습니다. 각 조합의 실제 관측 확인이 별도로 필요합니다.

[Coin Metrics 공식 정의](https://docs.coinmetrics.io/network-data/network-data-overview/mining/hash-rate)에서 BTC·DOGE·BCH·ETC·LTC는 TH/s, DASH·ZEC는 GH/s입니다. 기존 운영 응답에서 DASH·ZEC 값에 TH/s가 붙는 오류를 확인했고, 새 UI 검사에서 DASH의 GH/s와 BTC의 TH/s를 구별했습니다. 서로 다른 해시 함수의 수치 크기를 보안 순위로 비교하지 않습니다.

ETH는 [2022-09-15 Merge 이후 PoS](https://ethereum.org/roadmap/merge/)입니다. ETH나 그 위의 토큰에 BTC 채굴 모형을 붙이지 않습니다. DOGE는 [Scrypt 병합 채굴](https://dogecoin.com/dogepedia/how-tos/mining-dogecoin/)을 사용하므로 BTC 해시 리본의 성과 해석이나 SHA-256 전력 비용을 그대로 옮기지 않습니다.

## 3. 검증 범위와 실제 원천 표본

### 계산 검사

새 `tests/asset-rainbow.test.ts`, `tests/hash-ribbons.test.ts`의 **25개 검사를 통과**했습니다. 별도의 배치 최소제곱 회귀·잔차 분산과 단순 합계 기반 이동평균을 비교합니다. 테스트에는 최소 표본, 평탄값, 작은 가격, 확정 시각, 결측, 중복·역순, 미래 추가, 과거 수정, 더 오래된 이력, 고정 기준일 버전, 가격 확인의 중복 방지와 극단적 수치 범위를 포함합니다.

초기 21개 검사에서는 19개 통과·2개 실패가 있었습니다. 평탄한 해시 평균 뒤의 첫 하향 교차가 누락되는 초기 상태 처리 결함을 수정했고, 이후 가격 결측 주기와 고정 원장 검사를 보강해 최종 25개를 통과했습니다. 표준편차 0이나 수치 실패를 정상 위치 점수로 바꾸는 완화는 하지 않았습니다.

### 브라우저 검사

`e2e/indicator-models-032.spec.ts`는 명시적인 합성 JSON 관측을 격리된 fixture 서버에서 제공합니다. 운영 사이트나 공급자를 대신 검사한 것으로 표현하지 않습니다. 마지막 파일 구성은 **16개 시나리오 × Chromium·WebKit = 32개**이며 Playwright 목록·구문 검사를 통과했습니다. 최종 파일의 전체 실행 결과는 소스 동결 후 통합 검증 기록으로 확인해야 합니다.

| 실행 | 결과 | 확인한 내용과 처리 |
|---|---|---|
| 첫 Chromium 10개 | 8 통과·2 실패 | 첫 화면의 lazy route 대기와 60일 문구의 exact locator 실패 |
| locator 수정 후 두 엔진 20개 | 19 통과·1 실패 | Chromium 10개 통과, WebKit 9개 통과. 5번 전체 페이지를 여는 단일 guard 검사가 전체 45초를 소진 |
| 최종 파일 | 16개 시나리오·32개 목록 확인 | guard 5종을 독립 검사로 분리. 테스트 45초·기대 12초·재시도 0 기준 유지. 최종 실행 대기 |

첫 실패에서 화면은 `화면을 열고 있습니다…` 상태였고 차트 요소가 없었습니다. trace의 안전한 필드만 확인했을 때 Vite 개발용 React·React DOM·라우터·아이콘 번들이 HTTP 200 응답까지 약 26.9~27.1초, 상세 모듈은 약 3.86초 걸렸습니다. 개발 fixture의 JS 전달 지연은 확인했지만 정확한 원인은 확정하지 않았으며, 운영 번들의 지연이나 모형 계산 결함과 동일하게 취급하지 않습니다.

60일 준비 문구는 실제 화면에 올바르게 표시됐습니다. 제목과 본문이 함께 있는 상태 요소에 exact 문자열 locator를 사용한 검사 결함을 regex locator로 수정했습니다. 관측 30개라는 수치와 계산 준비 조건은 그대로 검사합니다.

WebKit guard 실패는 다섯 번째 잘못된 설정 화면까지 확인한 뒤 `현재 모델로 열기` 클릭에서 전체 테스트 시간이 만료됐습니다. model·anchor·origin·source·unit을 각각 독립 검사로 분리해 잘못된 설정의 이력 요청 0건, 명시적 복구 후 요청 1건을 각각 확인하도록 정리했습니다. HMR이 실행 중 관측됐으나 실패 원인으로 단정하지 않습니다.

실패 자료는 Git에서 제외된 `work/browser-checks/1791886094212-83016`, `work/browser-checks/1791886338251-76632`에 보존했습니다. 성공만 남기거나 실패를 최종 통과로 덮어쓰지 않습니다.

최종 시나리오는 독립 회귀 위치와 실제 표시, 기간 변경에 따른 확대 구간 변화·전체 850개 표본 유지, 저장 설정 복원과 원천 수정 안내, 설정 오류 차단·복구, 해시 사건과 정확한 날짜 고정, 60일 준비 조건, 가격 조건 미확보, PoW 단위·ETH 미지원, 수정·철회·누락된 기존 관측 링크를 검사합니다.

## 4. 채굴 전력·생산 비용의 제공 한계

채굴 비용 지표는 이번 계산 모듈에 구현하지 않았습니다. 기존 HashRate·신규 발행량만으로 실제 전력량·글로벌 하드웨어 구성·전력단가·사업 비용을 알 수 없기 때문입니다.

[Capriole 생산비 설명](https://capriole.com/bitcoins-production-cost)과 [Cambridge 방법론](https://ccaf.io/cbnsi/cbeci/methodology)에 따르면 전력 비용은 전력 사용량, 전력단가, 신규 발행량 등의 입력에 의존합니다. 전체 생산비에는 전력비와 다른 운영 비용의 비중 등에 대한 가정이 추가됩니다. Cambridge의 전력 사용량도 실제 계측 총량이 아니라 장비 효율과 채굴 수익성 등의 가정을 사용한 추정입니다.

검증되지 않은 고정 효율값이나 BTC 비용을 다른 자산에 재사용해 실측 비용·가격 하한처럼 표시하지 않습니다. 검증된 입력과 이용 조건을 확보하기 전에는 공식 참고 자료를 연결합니다. 실기기 Safari·VoiceOver와 사람 대상 사용성 검사는 이 계산·fixture 검사로 대체하지 않습니다. 48시간 대기는 추가하지 않습니다.
