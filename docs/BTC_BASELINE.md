## 실제 데이터 검산

- 초기 온체인 6,470개 날짜 중 유효 자본총액 관측은 5,878일입니다. 결측과 0원 자료를 MVRV로 대체하지 않았습니다.
- MVRV-Z 5,514개 날짜를 Python `statistics.pstdev` 계산과 비교했습니다. 최대 절대 오차는 `2.6645352591003757e-15`입니다.
- 화면 MVRV와 `market_cap / realized_cap`의 최대 절대 오차는 0입니다. 원천의 별도 MVRV 필드는 반올림 차이가 있어 보존하되 화면 산식과 구분했습니다. [데이터 정의](DATA.md)를 참고하세요.
- 상승·하락·횡보·파동과 거래소 4개 실제 표본, 합계 8개 기술지표 사례를 독립 계산과 비교했습니다.
- UTC 주·월 경계, 윤년, 결측 구간, 5,100일 자료의 월봉 페이지 경계, 병렬 조회 결과 보존, 미래 데이터 미사용을 테스트했습니다.
- 공개 API에서 잘못된 자산·시장·봉·범위를 거절합니다. 429·빈 응답·조용히 끊긴 WebSocket·재계산 도중 장애에서도 0을 최신값으로 만들지 않는지 확인했습니다.

원본과 검산 로그는 `work/raw/`, `work/independent-verification.json`에 있습니다. 재현용 참조값은 `tests/fixtures/`에 포함했습니다.

## 공개 운영과 복구

신규 D1 `btc-desk`를 생성했습니다. 초기 적재 17,405개 SQL 문장, 34,810행 쓰기, 약 3.92MB를 확인했습니다. 공개 조회는 인덱스와 공유 캐시를 사용하고, 전체 과거 수집·재계산은 한 Worker 요청에 넣지 않습니다.

초기 Binance REST 연결은 공개 서버에서 403/451을 반환했습니다. 공식 WebSocket API의 `ticker.24hr`·`klines`로 바꾸고 실제 응답과 Cron 갱신 성공을 확인했습니다. 다른 거래소의 가격으로 대체하지 않았습니다. 서버 위치는 서울 지역 배치 힌트를 사용해 ICN 데이터베이스와의 통신 지연을 줄였습니다.

- 로컬 백업→별도 파일 복원: 6개 테이블 해시 일치, SQLite 무결성 `ok`.
- 운영 D1 SQL 내보내기→별도 로컬 SQLite 복원: 무결성 `ok`, 당시 가격 10,920행·온체인 6,470행 복구. 운영 DB를 덮어쓰지 않았습니다.
- Worker 롤백: 동일한 검증 코드를 두 번 배포한 후 `55c6e499-db88-4cf4-9511-652a6442c6cc`에서 `d88a7ee6-1acd-41b5-9db4-427c58bb8e3e`로 실제 복귀하고 공개 검사를 통과했습니다. 이후 전체화면의 종료 상태와 화면 크기 변경 시 시간 범위 유지를 보완한 최신 버전은 `5d9b11ed-d2f1-412b-a6be-11aad33a7c1c`입니다.
- 새 원격 D1에 복구하고 운영 바인딩까지 전환하는 장애 훈련은 실행하지 않았습니다. 관련 절차는 [운영 안내](OPERATIONS.md)에 있습니다.

## 성능·무료 한도

가격 이력 페이지를 최대 4개씩 병렬 조회하고, RSI 요약을 캐시했습니다. 원격 D1 쿼리 통계에서 가격·온체인 조회의 읽기 효율은 약 1, 평균 SQL 시간은 표본별 약 0.6~0.8ms였습니다. 이는 네트워크 왕복 시간을 포함하지 않습니다.

차트 DOM의 데이터 설정 이후 두 화면 프레임이 지난 시각을 기록했습니다. 최적화 전 약 6.1초, 이후 PC 약 3.1~4.1초, 모바일 재조회 약 2.6초였습니다. 브라우저·서버 캐시와 네트워크가 다른 소수 표본이므로 **모든 신규 접속에서 3초 이내 목표를 달성했다고 판정하지 않습니다.**

최적화 후 공개 Worker 버전의 실행 표본 38개에서 CPU 0~10ms, 실행 실패 0회를 확인했습니다. 최적화 전에는 13ms 표본도 있었으며 기술지표 요약 캐시를 추가했습니다. `work/runtime-metrics.jsonl`은 방문자 IP·헤더 없이 경로·CPU·결과만 저장합니다. 소수 표본의 최대값으로 모든 요청의 한도 준수를 보장하지 않습니다.

D1 초기 쓰기·용량과 개별 쿼리 통계는 확인했지만, 전체 계정의 장기 누적 사용량과 방문자 증가 시 비용은 48시간 관찰에서 추가 확인해야 합니다. 유료 플랜으로 전환하거나 결제를 진행하지 않았습니다.

## 48시간 관찰: 진행 중

- 정상 공개 검사 시작: 2026-09-20 01:27:01 KST.
- 48시간 경과: 2026-09-22 01:27:01 KST.
- Codex 자동화: `BTC Desk 공개 운영 48시간 확인` (`btc-desk-48`), 매시간 48회.
- 조회 로그: `work/observation.jsonl`. 초기 실패 기록도 삭제하지 않았습니다.
- 의미 있는 장애·회복·완료 시 알리고 같은 상태가 계속되면 알리지 않습니다.

48시간 종료 후 실제 갱신 진행, API 실패, 지연 구간, 관찰 공백과 사용량을 이 문서에 추가해야 합니다. 현재는 완료로 표시하지 않습니다.
