# 0.35 데이터 이력·시세 전달·VPS 로딩

기존 차트와 화면 구성을 유지하며 전체 이력 복구와 시세·정적 파일 전달 경로를 보완합니다. [검증 기록](audit-35/README.md)의 실행 시점과 결과를 함께 확인합니다. 구현·수집·CI·배포를 같은 완료 상태로 취급하지 않습니다.

## 적용 범위

- Upbit에서 같은 밀리초에 여러 체결이 발생한 경우 더 늦은 공급자 이벤트의 가격을 전달합니다. 실제 체결 시각과 공급자 이벤트 시각은 구분합니다. 연결을 종료하거나 바꾼 뒤 늦게 해제된 메시지는 받지 않습니다.
- 브라우저와 서버 모두 실제 체결의 300초 유효성·미래 시각 허용 기준을 유지합니다. 거래가 없는 종목을 새 거래처럼 표시하지 않습니다.
- 정적 JS·CSS는 빌드 때 압축하고 원본 내용 해시로 찾습니다. 요청 중 고압축 작업을 하지 않으며 손상·내용 불일치·이전 자산은 기존 응답으로 복구합니다. HTML·API·SSE의 기존 정책은 보존합니다.
- 선물 과거 복구는 이번에 승인된 전용 실행으로 제한합니다. 평상시 하루 10,000개 후보 제한은 유지하고, 일시적인 확대에는 명시적인 실행 인수·만료·공유 예산·호출 간격·자원 보호·체크포인트를 적용합니다. 기존 일일 예약량을 초기화하지 않습니다.
- 150개 자산의 원천별 이력은 압축 보관본과 최근 관측을 함께 확인합니다. 원천 응답에 없는 관측을 만들거나 다른 거래소·통화의 이력을 붙이지 않습니다. 일봉·주봉·월봉 전체 이력과 기존 시간봉 정책을 구분합니다.

## 운영 원칙

공간 확인은 실제 일반 사용자 가용량을 사용하며 8GiB 과거 수집 보호 기준을 유지합니다. 운영 DB·개인 자료·다른 프로젝트를 삭제하지 않습니다. 수집 최신값과 과거 채우기는 별도로 운영합니다. 내부 수집 시각·복구 과정·내보내기·공유·날짜별 수치 패널을 공개 화면에 추가하지 않습니다.

백업은 새 격리 파일로 복원해 스키마·인덱스·관측 내용과 무결성을 대조합니다. 배포는 원격 CI와 main 확인 후 필요한 서비스만 교체하고 기존 릴리스의 복구 경로를 유지합니다. 48시간 대기는 추가하지 않습니다. 실제 Safari·VoiceOver·실물 휴대폰과 사람 대상 평가는 자동 검사와 구분합니다.

## 원천의 계약

- [Upbit 일봉](https://docs.upbit.com/kr/reference/list-candles-days): 거래가 발생한 구간에만 캔들을 제공합니다. 달력의 빈칸만으로 수집 누락을 확정하지 않습니다.
- [Binance 시장 데이터](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/market-data-endpoints): 선택한 거래쌍의 실제 OHLC와 체결을 사용합니다.
- [Bybit 미결제약정](https://bybit-exchange.github.io/docs/v5/market/open-interest): 계약·단위·관측 주기를 구분하고 제공된 범위만 복구합니다.
- [Coin Metrics 접근 안내](https://docs.coinmetrics.io/getting-started): 자산·지표별 실제 무료 응답과 관측 기간을 대조하고 이용 조건을 보존합니다.
