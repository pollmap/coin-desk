# 0.30 검증 기록

구현은 같은 지표 비교, 최근 확정값과 탐색 미리보기 분리, 공유·저장·복원, 원천별 이력 조회와 읽기 캐시입니다. [변경 설명](../RELEASE30.md).

## 데이터 범위

2026-10-11 10:47:44 UTC의 읽기 전용 SQLite 검사에서 150개 자산, 482개 가격 원천·봉 조합, 442개 온체인·내부 가격 조합, 143개 USD 참조가격, 680개 선물 지표 조합을 대조했습니다. 모든 조사 조합에 관측이 있었고 온체인 coverage 인덱스와 실제 월별 저장의 차이는 0입니다. 참조가격의 저장 시작이 등록된 최초 원천 날짜보다 늦는 사례는 없었습니다. 이 수치는 공급자가 제공한 전체 과거 자료를 매번 독립 재수집했다는 뜻은 아닙니다.

내부 달력 공백은 가격 3,602개, 온체인 84개, 선물 73개입니다. 거래 없음·현재 원천 미제공·수집 누락·수정 및 철회는 원천과 대조한 범위에서만 분류합니다. 원인 불명의 값을 보간하지 않습니다.

감사용 백업 6개를 SHA-256·SQLite 전체 테이블 내용·복원 검사 후 sidecar와 함께 tar.gz에 보존했습니다. 운영 DB·일일 백업·현재 및 직전 릴리스의 감사 백업은 보존했습니다. 여유 공간은 약 8.67GiB가 됐으며 8GiB 보호 기준은 유지했습니다. 압축 작업의 첫 실행은 마지막 폴더 이름 검사에서 중단됐고, 검증된 앞선 압축본을 재사용해 완료했습니다.

## 검사와 실패 기록

- 계산·타입·서버·복구 및 브라우저 검사는 완료한 실행별로 기록합니다. 독립 Decimal 계산의 기존 밴드·슈퍼트렌드 검사를 유지합니다.
- 초기 로컬 전체 브라우저 실행에서는 Chromium `Target crashed`가 여러 번 발생했습니다. 원인을 확정하지 않았고 성공 처리하지 않았습니다. WebKit 320px 비교 도구 줄바꿈 결함도 확인해 수정했습니다. 수정 중 진행한 실행은 최종 코드 회귀 증거로 사용하지 않으며 전체 판정은 변경을 멈춘 원격 PR·main CI를 기준으로 합니다.
- 새 캐시가 DB 없는 스트림 전용 서버에서도 SQLite를 초기화하던 결함을 서버 회귀 검사에서 발견해 수정했습니다. 손상된 시세 JSON이 이력 조회 전체를 실패시키지 않도록 분리했습니다.
- 변경 전 초기 로딩은 주소별 20개 신규 브라우저 문맥, 1280×800, 다운로드 10Mbps·업로드 5Mbps·추가 지연 0·CPU 1배에서 측정했습니다. Pages LCP p95 1,512ms·최악 5,392ms, VPS p95 3,156ms·최악 5,696ms였습니다. VPS는 2.5초 목표에 미달했습니다. 수정 후 같은 조건과 실제 SSE 100명 결과는 별도로 기록합니다.

## 배포와 제한

배포·백업·원격 CI·공개 파일 대조·실화면·자연 갱신은 실행 후 근거를 추가합니다. 아직 실행하지 않은 항목은 위 통과 수치에 포함하지 않습니다. 기존 API 외 수집기·시세 허브·DB 스키마·예약 작업을 불필요하게 재배포하지 않습니다.

실제 Apple Safari·VoiceOver 및 처음 사용하는 사람의 과제 검사는 별도 미검증입니다. WebKit·자동 접근성 검사가 이를 대신하지 않습니다. 48시간 대기는 적용하지 않습니다.
