### 0.4.0 장기 USD 참조가격

홈의 BTC·DOGE·ETH 전체 흐름은 [Coin Metrics PriceUSD 정의](https://docs.coinmetrics.io/network-data/network-data-overview/market/price)에 따른 **USD 일별 종가 참조가격**입니다. 무료 Community API `timeseries/asset-metrics`의 `metrics=PriceUSD`, `frequency=1d`를 사용합니다. 날짜 표시는 해당 UTC 일자를 뜻하며, 하루가 마감된 유효 양수 값만 보관합니다. 거래소 OHLCV·거래량·Bitview의 추정 USD 가격과 각각 다른 시계열입니다.

- 0.4.0 최초 적재 총 **14,589개** 값을 보관 원본과 공개 API 전체 페이지로 검산했습니다. 지원 구간 안에서 세 자산 모두 날짜 중복·역전·내부 누락 구간이 없습니다. 시작일 이전의 null·미제공 가격은 채우지 않습니다.
- 이 일별 값 하나로 시가·고가·저가·거래량을 만들지 않습니다. 거래소 차트와 코인 성과 비교는 계속 Binance 또는 Upbit의 실제 캔들을 사용합니다. 온체인 비교선도 계속 Bitview 가격을 사용합니다.
- [Coin Metrics 공식 데이터 저장소](https://github.com/coinmetrics/data/blob/master/README.md)는 Community 데이터에 **[CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/)**를 명시합니다. 화면에 Coin Metrics·PriceUSD·라이선스·비상업 이용을 표시하며 상업용 재사용 권한으로 확대 해석하지 않습니다. 정상화는 UTC 확정일·유효 가격 필터링과 숫자 변환이며 기존 가격값을 보간하지 않습니다.
- `bootstrap_reference.py`는 자산별 원본 JSON, SQL, 수집 시각·시작/종료일·null 개수·누락 구간·SHA-256 감사 자료를 `work/reference/`에 남깁니다. `import_reference.mjs`는 로컬 SQLite에 적재합니다. 공개 D1 적재 절차는 [운영 안내](OPERATIONS.md)에 있습니다.
- `verify_reference.py --base ...`는 모든 페이지의 날짜 고유성·순서와 보관 원본 날짜 포함을 확인하고, 값은 상대 허용오차 `1e-12`, 절대 허용오차 `1e-14`로 비교합니다. 이후 새 관측이 추가되어도 보관 원본의 값을 빠뜨리지 않았는지 검증할 수 있습니다.
- 정기 수집은 6시간 목표, 한 작업 최대 32개 원천 날짜입니다. 최신 저장일의 이틀 전부터 수정값을 확인하며 따라잡을 이력이 남으면 커서를 보관합니다. 유효 가격이 없는 페이지를 받았다는 이유로 실제 데이터 기준일을 앞으로 옮기지 않습니다. 과거의 더 오래된 수정은 전체 재수집·적재·검산으로 반영합니다.

## 가격과 변동률

- 거래소 캔들은 해당 시장의 원본 OHLCV입니다. 환율로 원화를 생성하지 않습니다.
- Binance 시세는 최근 24시간 ticker입니다.
- 운영 수집은 [Binance 공식 공개 WebSocket API](https://developers.binance.com/en/docs/products/spot/web-socket-api)의 `ticker.24hr`·`klines`입니다. 초기 대량 수집은 [공개 REST API](https://developers.binance.com/en/docs/products/spot/faqs/market_data_only)입니다. 프로토콜이 달라도 시장은 해당 자산의 USDT 거래쌍으로 동일합니다. 공개 서버의 REST 접근 거절을 WebSocket의 실제 응답 성공으로 해결했으며 다른 거래소 가격을 Binance로 표시하지 않습니다.
- Upbit ticker의 `signed_change_rate`는 UTC 전일 종가 기준이므로 24시간 수익률로 쓰지 않습니다. 현재가와 24시간 전의 **1분봉 종가**로 근사한 변동률을 표시하고 `24H≈`로 안내합니다. 기준 봉 시각 `referenceAt`을 반환하며 5분 이상 오래된 기준 봉은 사용하지 않습니다.
- Upbit 고가·저가는 원천의 UTC 당일 값이고, 거래대금은 원천의 실제 최근 24시간 값입니다. 화면에서 기준을 구분합니다.
- 온체인 비교선은 Bitview의 **추정 USD 가격**입니다. 초기 과거 가격 자료와 이후 온체인 oracle 추정값으로 구성되며 거래소 USDT/KRW 가격과 혼합하지 않습니다. [가격 모듈 설명](https://github.com/bitcoinresearchkit/mono/blob/main/crates/brk_oracle/README.md)

## 계산

| 지표 | 구현 정의 |
|---|---|
| 128·200·365일선 | 확정 일봉 종가의 단순평균. 필요한 관측 수 전에는 없음 |
| 200주선 | UTC 월요일 시작 주봉의 확정 종가 200개 평균 |
| RSI 14 | 선택한 봉 기준. 첫 14개 변화량 평균으로 초기화하고 이후 Wilder 평활화. 변화가 없으면 50, 손실만 없으면 100 |
| 볼린저밴드 | 선택한 봉의 20개 종가 단순평균 ± 모집단 표준편차 2배 |
| MVRV | Bitview `market_cap / realized_cap`, 두 값 모두 양수일 때 |
| NUPL | Bitview `(market_cap-realized_cap)/market_cap`, 두 값 모두 양수일 때. API는 비율, 화면은 % |
| MVRV-Z | 두 자본총액 차이 / 해당일까지의 유효 시가총액 모집단 표준편차. 최소 365개 유효 일별 표본. 분산 0이면 없음 |
| 실현가격·보유자 지표·SOPR | Bitview의 원천 값과 해당 집단 정의. STH/LTH 값을 타사 데이터와 혼합하지 않음 |

MVRV-Z 계산의 n·평균·M2를 각 날짜와 함께 저장합니다. 최근 구간 수정 시 그 직전 날짜 상태부터 다시 계산하므로 미래 값을 과거 값에 사용하지 않습니다. 전체 계산 시작일과 최초 표시일은 다릅니다. `calculationStart`는 첫 유효 자본총액 날짜이며 첫 Z 값은 365개가 쌓인 뒤입니다. [표준 MVRV-Z 개념](https://docs.glassnode.com/further-information/metric-guides/mvrv/mvrv-z-score)

### 초기 MVRV 정밀도 차이

원천 MVRV와 자본총액 비율을 비교했을 때 초기 소수 가격 구간에서 최대 약 49.62%의 상대 차이를 확인했습니다. 예를 들어 반올림된 0.01 USD 실현가격으로 계산한 비율과 반올림 전 자본총액 비율은 다릅니다. 화면은 자본총액 비율을 사용하며 원천 값은 `mvrv_source`, `nupl_source`로 보존합니다. 2015년 이후 원천 MVRV와의 최대 상대 차이는 이번 표본에서 약 0.00357%입니다. 이를 타사 MVRV와 완전히 같은 값이라고 표시하지 않습니다.

## 시간·결측·집계

- 저장은 UTC epoch 초입니다. 시간 표시·수집 시각은 KST, 일·주·월 마감은 UTC 기준입니다.
- 주봉은 월요일 00:00 UTC, 월봉은 달력 월의 1일입니다. 4시간봉은 UTC 00·04·08·12·16·20시 기준입니다.
- 거래 없는 구간·원천 누락은 합성 캔들로 채우지 않습니다. 거래량은 관측 봉만 합산합니다. 시작 시점의 일부 주·월은 확보 가능한 봉으로 표시됩니다.
- 데이터 페이지 끝이 주·월 중간이면 다음 페이지로 넘겨 부분 집계가 확정된 값으로 중복되거나 누락되지 않게 합니다. `from`이 봉 중간이면 해당 봉의 시작까지 포함합니다.
- 기술지표는 유효 관측 봉 개수 기준입니다. 공백이 있다고 0이나 직전 종가를 넣지 않습니다. 대시보드 RSI·이동평균 요약은 확정 일봉 기준이고, 선택한 차트의 RSI·밴드는 진행 중인 마지막 봉에 따라 변할 수 있습니다.
- 일·주 이동평균을 시간봉에 표시할 때 해당 일·주의 마감 이후에만 값이 나타납니다.

## 조회 계약

공개 API는 GET만 지원하며 거래·계정·쓰기 API가 없습니다.

| 경로 | 주요 매개변수 |
|---|---|
| `/api/v1/overview` | `asset=BTC`, `market=binance 또는 upbit` |
| `/api/v1/candles` | 자산·시장, `interval=1h/4h/1d/1w/1M`, UTC초 `from/to`, `limit≤1000` |
| `/api/v1/metrics` | 등록된 BTC 지표 정의 |
| `/api/v1/series` | `asset=BTC`, `metric`, `from/to`, `limit≤1000` |
| `/api/v1/reference` | `asset=BTC/DOGE/ETH`, UTC초 `from/to`, `limit≤1000`; USD 일별 참조가격 |
| `/api/v1/status` | 수집 시각·원천 기준일·오류·재시도·확보 이력 |
| `/api/v1/health` | 매개변수 없음; 운영 정상 조건 200, 실패·지연 사유가 있으면 503 |

시계열은 `data`, `meta`, `nextCursor`로 반환합니다. 온체인은 같은 원천의 `price` 배열을 함께 반환합니다. `meta`에는 단위·시장·출처·기준일·수집 시각·계산 버전·지연 상태가 포함됩니다. 온체인 응답에 원천 버전과 계산 시작일을 둡니다. 결측은 임의의 숫자로 만들지 않으며 시계열에서는 해당 점을 생략합니다.

장기 참조가격 응답의 `data`는 `{time,value}` 배열이고 `price`는 빈 배열입니다. `meta.unit=USD`, `source=Coin Metrics Community · PriceUSD`, `calculationVersion=coinmetrics-priceusd-utc-close-v1`, `priceBasis`, `historyStart`를 제공합니다. 조회 범위는 `from` 포함·`to` 제외이며 추가 페이지가 있으면 마지막 관측 다음 UTC 날짜를 커서로 반환합니다. 마지막 정상 수집이 7시간을 넘거나, 유효 가격의 최신일이 3일보다 오래됐거나, 원천 실패가 남으면 `stale`로 표시합니다.

## 보관

Python은 원본 URL·수집 시각·응답을 `work/raw/*.json.gz`로 보관하고 SQL을 생성합니다. 정기 수집은 D1 `raw_samples`에 온체인 원본 표본과 가격 정규화 표본을 원천별로 교체 보관합니다. 정규화 가격, 온체인 원천 필드, 자체 계산 필드를 구분합니다. 보유자 주소·개인 거래 내역은 수집하지 않습니다.

0.4.0 참조가격은 `reference_prices(asset,time,value,fetched_at)`에 따로 보관하며 값이 바뀌지 않으면 같은 관측 행을 다시 쓰지 않습니다. 수집 성공 시각은 `ingestion`에 별도로 기록하므로 관측 행의 `fetched_at`과 최신 조회 성공 시각은 다를 수 있습니다. `cron_state`·`cron_runs`는 시장값과 분리한 운영 기록입니다. `0004_automation.sql`, `0005_reference_prices.sql` 마이그레이션이 필요합니다.

추가 기술지표 정의:

| 항목 | 산식과 제한 |
|---|---|
| 사용자 SMA | 기간 2~1,000의 산술평균. 일·주 확정 종가 또는 선택한 차트 봉 종가 |

| 사용자 볼린저밴드 | 기간 2~1,000의 SMA ± 모집단 표준편차 × 배수(0.5~5) |
| MACD | EMA(단기)−EMA(장기), 신호선=MACD의 EMA(신호기간), 각각 SMA 초기화. 기본 12·26·9, 각 기간 2~1,000 및 단기 < 장기. 히스토그램=MACD−신호선 |

동시 표시 최대 10개, RSI·볼린저밴드·MACD는 각 1개입니다. 같은 SMA/EMA 기간·기준은 중복 제거합니다. URL 식별자는 `sma:55:d`, `ema:20:bar`, `rsi:7:bar`, `bb:20:bar:2.5`, `macd:8:bar:21:5` 형식입니다. 기존 `sma200`, `sma200w`, `rsi`, `bb`, `macd` 링크도 유지합니다. 그린 선은 URL로 공유하지 않습니다.

## 도미넌스 정의와 원천

CoinGecko 무료 API는 초기 조사에서 응답했지만 운영 Worker에서 반복 429가 발생했습니다. 현재는 CoinLore·DefiLlama로 고정하며 자동으로 제공자를 바꿔 시계열을 연결하지 않습니다. 기존 `coingecko` 실패 기록은 보존하되 상태 API에서 `active:false`로 표시합니다.

| 데이터 | 실제 API | 계산·시점 |
|---|---|---|
| 전체 시장 USD 시가총액 | CoinLore `/api/global/`의 `total_mcap` | 별도 원천 기준시각이 없어 조회 시각 표시 |
| 8개 자산·USDT·USDC | CoinLore `/api/ticker/?id=...`의 `market_cap_usd` | 동일 원천 개별 시가총액 / 전체 × 100 |
| 스테이블 전체 ≈ | DefiLlama `stablecoincharts/all` 마지막 일별 관측의 `totalCirculatingUSD` | 모든 USD 환산 필드 합 / CoinLore 전체 × 100. 서로 다른 원천·시점의 근사값 |

DefiLlama의 `totalCirculating`은 네이티브 통화 수량이므로 합산하지 않습니다. 스테이블 전체에 USDT와 USDC가 포함되며 세 항목을 합쳐 100% 차트로 만들지 않습니다. 공급·분류·가격 평가 차이로 CoinGlass·TradingView·CoinGecko 지수와 다릅니다. CoinLore의 응답 조회 시각은 원천 체결 시각 보증이 아닙니다.

`GET /api/v1/dominance`는 `coins`, 전체 시가총액, `source`, `asOf`, `fetchedAt`, `stale`, `calculationVersion`을 반환합니다. 각 코인에 분자 시가총액, 기준 시각, 원천, `timeBasis`가 포함됩니다. `retrieved`는 조회 시각, `daily`는 일별 데이터 기준일입니다. 개별 시장값은 2시간, DefiLlama 일별값은 3일을 초과하면 지연입니다.

`GET /api/v1/dominance/history`는 동일 계산 버전의 최근 최대 1,000회 실제 관측값입니다. 소스가 지연되거나 전체 항목이 빠지면 새로운 정상 이력으로 기록하지 않습니다. 최초 관측 이전의 과거 자료를 생성하지 않으며 관측 시각을 정각으로 소급하지 않습니다. 원본 표본은 D1 `raw_samples`에 원천 URL과 함께 보존합니다.

## 0.3에서 도입한 조회 계약

`overview.quote.change24h`는 숫자 또는 `null`입니다. Upbit의 전일 같은 시각 1분봉이 없거나, 기준보다 5분 이상 오래됐거나, 해당 비교 요청만 실패하면 현재가·거래대금·UTC 당일 고저가는 그대로 검증·제공하고 등락률만 결측으로 반환합니다. `changeUnavailableReason`에 한국어 이유, `referenceAt`에 실제로 확보한 비교 분봉 시각 또는 `null`을 기록합니다. 거래가 없던 구간을 보간하거나 전일 대비로 바꾸지 않습니다.

현재 체결 시각이 5분보다 오래됐거나 미래·비정상 현재가이면 별도의 시세 실패로 처리합니다. 파생 등락률 결측을 현재가 수집 실패와 구분하며, 공개 점검 결과의 `warnings`와 `issues`도 분리합니다. 정상 저장해 둔 시세가 시간이 지나 지연되면 화면의 지연 안내는 유지합니다.

조회 API는 허용한 단일 파라미터만 받으며 모호한 중복, 임의 캐시 분리용 파라미터, 잘못된 수치 범위를 거부합니다. 조회 기본값과 파라미터 순서를 정규화해 같은 요청은 캐시를 공유합니다. 방문자 요청의 시세는 180초 갱신 잠금과 30초 응답 캐시를 사용하므로 화면에는 정확한 최대치 대신 약 3분 주기와 실제 거래 시각을 표시합니다. 0.4.0은 아래 서버 독립 수집을 추가합니다.

## 0.4.0 기간·비교·지표 활용 계약

기간 프리셋은 `1m`, `3m`, `6m`, `ytd`, `1y`, `3y`, `5y`, `all`입니다. 월·연 단위는 UTC 달력으로 역산하고 월말이 없는 날짜는 해당 월의 말일로 맞춥니다. `ytd`는 해당 연도 1월 1일, `all`은 해당 원천의 확보 시작일입니다. 첫 방문 기본값은 전체이며 이전 기본 기간은 버전 전환 때 한 번 갱신하고 이후 사용자가 저장한 기간과 명시한 URL을 존중합니다.

가격 차트의 직접 기간 입력은 KST 기준이고 비교 화면의 `from`·`to`는 **UTC 일자 `YYYY-MM-DD`**입니다. 비교의 직접 시작·종료일은 모두 포함합니다. 잘못된 날짜·한쪽 누락·역전·미래 종료일을 거부하며, 직접 기간을 쓰는 동안 일반 프리셋은 활성 표시하지 않습니다.

성과 비교 버전은 `common-utc-calendar-v2`입니다. 프리셋 역산 기준은 모든 선택 코인에 있는 **공통 최신 확정일**입니다. 첫 공통 종가를 100으로 맞추며, 올해 수익률은 1월 1일부터 확보된 첫 공통 종가를 시작값으로 사용합니다. 코인별 수집 시작이 늦거나 관측이 없으면 실제 비교 범위가 짧아질 수 있어 요청 기간·실제 기간·제한한 코인을 함께 표시합니다. CSV는 실제 공통 날짜의 원래 종가·시작 100 지수·수익률·계산 버전을 담습니다. 수익률·낙폭·변동성 산식과 결측 원칙은 유지합니다.

비교 데이터 로더는 첫 페이지 뒤 900일 구간으로 나누어 전체 자산을 합쳐 최대 4개 동시 요청을 허용합니다. 15분 캐시는 이미 확보한 범위를 포함하는 요청에 재사용하고, 수동 갱신 성공 시 같은 자산·시장의 오래된 캐시를 교체합니다. 실패·중단된 부분 결과는 완성된 캐시로 저장하지 않습니다.

12개 지표 안내는 [질문·설명 정의](../shared/metric-guides.ts)를 바탕으로 `질문 → 먼저 볼 것 → 함께 볼 것 → 해석의 한계`를 제공합니다. 설명·산식·예시를 검색하고 기술지표 적용 자산을 선택할 수 있습니다. 예시는 실제 최신 수치와 구분합니다. 같은 원천의 NUPL과 MVRV 관계 등 원자료가 겹치는 지표를 독립적인 근거로 중복 해석하지 않도록 설명하며 신규 점수나 매매 명령은 생성하지 않습니다.

## 0.4.0 서버 자동화와 상태

Cloudflare Cron은 방문자·PC와 독립적으로 매분 작업 하나를 실행합니다. 16개 자산·시장 시세는 4개 배치로 약 8분 주기를 목표로 하며 운영 지연 기준은 10분입니다. 시간봉·온체인은 1시간, 일봉은 6시간과 UTC 경계 우선 갱신, 참조가격·DefiLlama는 6시간, CoinLore는 1시간 주기입니다. 지연·백오프·온체인 재계산·초기 복구 중에는 실제 완료 시각이 달라질 수 있습니다.

`/api/v1/status`는 `automation`, 원천별 상태, `health`, `coverage`를 포함합니다. `automation`은 마지막 시작·완료·성공·작업·실행 결과·다음 분 경계·예정 작업·최근 20개 기록을 제공하며 전체 실행 기록은 최대 120개 슬롯으로 순환 보관합니다. HTTP 응답 성공, 수집 성공, 시장 데이터 기준일, 최신성은 각각 구분합니다. 공개 오류에는 인증·원문 응답·내부 경로 대신 정제된 사유를 제공합니다.

화면 현재가의 거래 시각이 5분을 넘는 `liveStale`와 서버의 10분 운영 지연은 별도 기준입니다. `health.ok`는 실행 정체·활성 원천의 실패·지연·누락 등 현재 조건을 평가하며 무료 CPU·D1 한도의 장기 충족이나 48시간 무중단을 보증하지 않습니다.

코인 비교 산식·공통 기간·CSV 계약은 [비교 문서](COMPARISON.md), 개인 설정과 결함 수정은 [레드팀 결과](REDTEAM.md)를 참고하세요.


## 0.6 전체 이력 조회 범위

`candles`, `series`, `reference`, `network`의 페이지 응답에는 기존 필드와 함께 `range: { from, to }`를 반환합니다. 단위는 UTC Unix 초이며 `from`은 포함, `to`는 제외입니다. 최초 요청에서 종료일을 생략하면 서버가 이를 확정합니다. 후속 병렬 구간은 그 범위 안에서만 생성합니다. 각 후속 응답의 `range`는 해당 하위 요청의 범위이며 클라이언트가 처음 확정한 전체 범위를 덮어쓰지 않습니다.

구버전 캐시에 `range`가 없으면 브라우저 시각으로 `to`를 만들지 않고 `nextCursor`를 순차 추적합니다. 페이지 실패를 전체 조회 완료로 승격하지 않습니다. 명시적으로 잘못된 미래 날짜를 전달하면 기존 서버 검증이 거절하며, 화면에는 한국어 오류와 재시도 방법을 표시합니다. 서버를 먼저 배포한 뒤 프런트엔드를 배포합니다.

## 0.7 분석 확장 데이터 계약

첫 화면의 BTC·DOGE·ETH 카드에는 선택한 시장의 현재가·24시간 변화와 **실제 체결 또는 관측 시각**을 표시합니다. 큰 전체 이력 차트는 Coin Metrics `PriceUSD` 일별 참조가격이며 거래소 캔들과 연결하지 않습니다. SOL·XRP·LINK·ONDO·PEPE는 접힌 영역과 기존 차트·비교에서 계속 조회할 수 있습니다.

BTC 사이클 선은 확보한 USD 참조가격의 **확정된 UTC 일별 종가**로 계산합니다. 200주선은 완성된 주봉 종가 200개, 2년선은 일별 종가 730개와 그 평균의 5배, Pi Cycle은 111일 평균과 350일 평균의 2배입니다. 필요한 과거 표본이 없으면 그 시점의 선을 생략합니다. 고점 대비 낙폭은 해당 날짜까지 관측된 종가 최고값을 분모로 계산하므로 미래 가격을 과거 기준에 넣지 않습니다. 이 선들은 차트 참고선이며 일정한 주기의 재현이나 수익을 보증하지 않습니다.

DOGE/BTC·ETH/BTC 상대가격은 같은 UTC 날짜에 모두 관측된 **USD 참조가격의 비율**입니다. 거래소의 DOGE/BTC·ETH/BTC 체결 시세가 아닙니다. 상대 성과는 공통 첫 날짜를 100으로 정규화합니다. 30·90일 상관관계는 양쪽 자산의 공통·연속 날짜별 로그수익률로 계산하며 결측 날짜를 메우지 않습니다. 최고점 대비 낙폭은 각각의 실제 관측 종가 최고값을 기준으로 합니다.

Coin Metrics Community의 추가 네트워크 지표는 `GET /api/v1/network`의 기존 시계열 계약에 포함됩니다. BTC·ETH의 `exchange_inflow`=`FlowInExNtv`, `exchange_outflow`=`FlowOutExNtv`, `exchange_balance`=`SplyExNtv`이며 단위는 해당 자산 수량입니다. `exchange_netflow`는 **같은 날짜의 원본 유입−유출을 십진수로 뺀 계산값**입니다. DOGE의 `blocks`=`BlkCnt`, `issuance`=`IssTotNtv`도 포함합니다. 지원 여부는 자산별로 등록하며 미지원 자산에 다른 코인의 값을 대입하지 않습니다. 거래소 주소 식별 범위는 원천에 의존하고 변경될 수 있으므로 `sourceStatus`(`reviewed` 또는 `flash`)와 수집 시각을 함께 제공하며 결측일은 생략합니다.

`GET /api/v1/derivatives?asset=BTC|DOGE|ETH&metric=funding|open_interest&from=&to=&limit=`는 Binance **USDⓈ-M USDT 무기한 계약 한 거래소**의 관측값만 조회합니다. `funding`은 원본 정산 비율에 100을 곱한 `%` 값이고, `open_interest`는 원본 `sumOpenInterestValue`의 **USDT 명목 가치**입니다. 응답에는 `data`, `price: []`, `range: {from,to}`, `nextCursor`, `meta.source/unit/market/dataAsOf/fetchedAt/historyStart/stale/calculationVersion/warning`을 포함합니다. 범위는 UTC Unix 초의 시작 포함·끝 제외이고, 커서는 마지막 반환 관측 이후입니다. 펀딩비는 실제 제공 첫 날짜부터 페이지 단위로 백필하며 미결제약정은 원천이 제공하는 최근 범위부터 축적합니다. 원천이 차단되거나 값이 없으면 빈 배열과 오류·지연 설명을 반환하고 시세를 추정하지 않습니다. 2026-09-23 공개 Worker에서는 Binance 선물 원천이 HTTP 403을 반환해 두 시계열 모두 **원천 연결 대기** 상태입니다.

`GET /api/v1/network-live?asset=BTC`는 mempool.space의 마지막 정상 관측을 반환합니다. 미확인 거래 건수·가상 바이트와 권장 수수료(`sat/vB`)의 **현재 추정치**로, 확정된 온체인 일별 기록과 별개입니다. 서버 Cron의 15분 목표 주기로 확인하고 실제 관측·수집 시각과 지연 여부를 표시합니다. 브라우저 방문이 수집을 시작하지 않습니다. 운영 상태와 원천별 실패·갱신 시각은 `/api/v1/status`와 `/api/v1/health`에서 확인합니다.
