# 데이터 정의서

기준일: 2026-09-20 KST. 원본을 사용한 구현이며 투자 수익 예측이나 매매 신호를 만들지 않습니다.

## 원천과 이력

| 데이터 | 원천 | 확보 이력 | 단위 |
|---|---|---|---|
| BTC 일봉 | Binance `BTCUSDT` | 2017-08-17부터, 최초 수집 3,321개 | USDT·BTC 거래량 |
| BTC 일봉 | Upbit `KRW-BTC` | 2017-09-25부터, 최초 수집 3,282개 | KRW·BTC 거래량 |
| BTC 시간봉 | 동일 거래소 | 최근 90일, 최초 각각 2,161·2,158개 | 동일 |
| BTC 온체인 일별 | Bitview bulk API | 2009-01-01~2026-09-18, 6,470개 날짜 | 지표별 정의 |

거래소 이력에는 진행 중인 마지막 봉이 포함됩니다. 온체인은 UTC 날짜가 마감된 관측값만 저장합니다. 이력 길이·최신일은 수집 시점에 따라 바뀌며 실제 상태는 `/api/v1/status`에서 확인합니다. 초기 온체인 기간의 가격·실현시가총액 0이나 결측을 정상 MVRV로 채우지 않습니다.

Bitview 요청은 `date,price,market_cap,realized_cap,mvrv,sth_mvrv,lth_mvrv,realized_price,sth_realized_price,nupl,sopr_24h`를 `index=day1`로 함께 조회합니다. 명시적인 `date` 배열에 맞추며 날짜·길이·시리즈 버전을 검증합니다. API의 정수 인덱스를 Unix 날짜라고 가정하지 않습니다.

## 가격과 변동률

- 거래소 캔들은 해당 시장의 원본 OHLCV입니다. 환율로 원화를 생성하지 않습니다.
- Binance 시세는 최근 24시간 ticker입니다.
- 운영 수집은 [Binance 공식 공개 WebSocket API](https://developers.binance.com/en/docs/products/spot/web-socket-api)의 `ticker.24hr`·`klines`입니다. 초기 대량 수집은 [공개 REST API](https://developers.binance.com/en/docs/products/spot/faqs/market_data_only)입니다. 프로토콜이 달라도 시장은 해당 자산의 USDT 거래쌍으로 동일합니다. 공개 서버의 REST 접근 거절을 WebSocket의 실제 응답 성공으로 해결했으며 다른 거래소 가격을 Binance로 표시하지 않습니다.
- Upbit ticker의 `signed_change_rate`는 UTC 전일 종가 기준이므로 24시간 수익률로 쓰지 않습니다. 현재가와 24시간 전의 **1분봉 종가**로 근사한 변동률을 표시하고 `24H≈`로 안내합니다. 기준 봉 시각 `referenceAt`을 반환하며 5분 이상 오래된 기준 봉은 사용하지 않습니다.
- Upbit 고가·저가는 원천의 UTC 당일 값이고, 거래대금은 원천의 실제 최근 24시간 값입니다. 화면에서 기준을 구분합니다.
- 온체인 비교선은 Bitview의 **추정 USD 가격**입니다. 초기 과거 가격 자료와 이후 온체인 oracle 추정값으로 구성되며 거래소 USDT/KRW 가격과 혼합하지 않습니다. [가격 모듈 설명](https://github.com/bitcoinresearchkit/mono/blob/main/crates/brk_oracle/README.md)

## 계산

| 지표 | 구현 정의 |
|---|---|
| 128·200·365일선 | 확정 일봉 종가의 단순평균. 필요한 관측 수 전에는 없음 |
| 200주선 | UTC 월요일 시작 주봉의 확정 종가 200개 평균 |
| RSI 14 | 선택한 봉 기준. 첫 14개 변화량 평균으로 초기화하고 이후 Wilder 평활화. 변화가 없으면 50, 손실만 없으면 100 |
| 볼린저밴드 | 선택한 봉의 20개 종가 단순평균 ± 모집단 표준편차 2배 |
| MVRV | Bitview `market_cap / realized_cap`, 두 값 모두 양수일 때 |
| NUPL | Bitview `(market_cap-realized_cap)/market_cap`, 두 값 모두 양수일 때. API는 비율, 화면은 % |
| MVRV-Z | 두 자본총액 차이 / 해당일까지의 유효 시가총액 모집단 표준편차. 최소 365개 유효 일별 표본. 분산 0이면 없음 |
| 실현가격·보유자 지표·SOPR | Bitview의 원천 값과 해당 집단 정의. STH/LTH 값을 타사 데이터와 혼합하지 않음 |

MVRV-Z 계산의 n·평균·M2를 각 날짜와 함께 저장합니다. 최근 구간 수정 시 그 직전 날짜 상태부터 다시 계산하므로 미래 값을 과거 값에 사용하지 않습니다. 전체 계산 시작일과 최초 표시일은 다릅니다. `calculationStart`는 첫 유효 자본총액 날짜이며 첫 Z 값은 365개가 쌓인 뒤입니다. [표준 MVRV-Z 개념](https://docs.glassnode.com/further-information/metric-guides/mvrv/mvrv-z-score)

### 초기 MVRV 정밀도 차이

원천 MVRV와 자본총액 비율을 비교했을 때 초기 소수 가격 구간에서 최대 약 49.62%의 상대 차이를 확인했습니다. 예를 들어 반올림된 0.01 USD 실현가격으로 계산한 비율과 반올림 전 자본총액 비율은 다릅니다. 화면은 자본총액 비율을 사용하며 원천 값은 `mvrv_source`, `nupl_source`로 보존합니다. 2015년 이후 원천 MVRV와의 최대 상대 차이는 이번 표본에서 약 0.00357%입니다. 이를 타사 MVRV와 완전히 같은 값이라고 표시하지 않습니다.

## 시간·결측·집계

- 저장은 UTC epoch 초입니다. 시간 표시·수집 시각은 KST, 일·주·월 마감은 UTC 기준입니다.
- 주봉은 월요일 00:00 UTC, 월봉은 달력 월의 1일입니다. 4시간봉은 UTC 00·04·08·12·16·20시 기준입니다.
- 거래 없는 구간·원천 누락은 합성 캔들로 채우지 않습니다. 거래량은 관측 봉만 합산합니다. 시작 시점의 일부 주·월은 확보 가능한 봉으로 표시됩니다.
- 데이터 페이지 끝이 주·월 중간이면 다음 페이지로 넘겨 부분 집계가 확정된 값으로 중복되거나 누락되지 않게 합니다. `from`이 봉 중간이면 해당 봉의 시작까지 포함합니다.
- 기술지표는 유효 관측 봉 개수 기준입니다. 공백이 있다고 0이나 직전 종가를 넣지 않습니다. 대시보드 RSI·이동평균 요약은 확정 일봉 기준이고, 선택한 차트의 RSI·밴드는 진행 중인 마지막 봉에 따라 변할 수 있습니다.
- 일·주 이동평균을 시간봉에 표시할 때 해당 일·주의 마감 이후에만 값이 나타납니다.

## 조회 계약

공개 API는 GET만 지원하며 거래·계정·쓰기 API가 없습니다.

| 경로 | 주요 매개변수 |
|---|---|
| `/api/v1/overview` | `asset=BTC`, `market=binance 또는 upbit` |
| `/api/v1/candles` | 자산·시장, `interval=1h/4h/1d/1w/1M`, UTC초 `from/to`, `limit≤1000` |
| `/api/v1/metrics` | 등록된 BTC 지표 정의 |
| `/api/v1/series` | `asset=BTC`, `metric`, `from/to`, `limit≤1000` |
| `/api/v1/status` | 수집 시각·원천 기준일·오류·재시도·확보 이력 |

시계열은 `data`, `meta`, `nextCursor`로 반환합니다. 온체인은 같은 원천의 `price` 배열을 함께 반환합니다. `meta`에는 단위·시장·출처·기준일·수집 시각·계산 버전·지연 상태가 포함됩니다. 온체인 응답에 원천 버전과 계산 시작일을 둡니다. 결측은 임의의 숫자로 만들지 않으며 시계열에서는 해당 점을 생략합니다.

## 보관

Python은 원본 URL·수집 시각·응답을 `work/raw/*.json.gz`로 보관하고 SQL을 생성합니다. 정기 수집은 D1 `raw_samples`에 온체인 원본 표본과 가격 정규화 표본을 원천별로 교체 보관합니다. 정규화 가격, 온체인 원천 필드, 자체 계산 필드를 구분합니다. 보유자 주소·개인 거래 내역은 수집하지 않습니다.

추가 기술지표 정의:

| 항목 | 산식과 제한 |
|---|---|
| 사용자 SMA | 기간 2~1,000의 산술평균. 일·주 확정 종가 또는 선택한 차트 봉 종가 |
| 사용자 EMA | 첫 N개 종가 SMA로 초기화, α=2/(N+1), EMAₜ=α·종가ₜ+(1−α)·EMAₜ₋₁ |
| 사용자 RSI | 기간 2~1,000, 기존 Wilder 방식. 선택한 봉 간격 |
| 사용자 볼린저밴드 | 기간 2~1,000의 SMA ± 모집단 표준편차 × 배수(0.5~5) |
| MACD | EMA12−EMA26, 신호선=MACD의 EMA9(SMA 초기화), 히스토그램=MACD−신호선 |

동시 표시 최대 10개, RSI·볼린저밴드·MACD는 각 1개입니다. 같은 SMA/EMA 기간·기준은 중복 제거합니다. URL 식별자는 `sma:55:d`, `ema:20:bar`, `rsi:7:bar`, `bb:20:bar:2.5` 형식입니다. 기존 `sma200`, `sma200w`, `rsi`, `bb` 링크도 유지합니다. 그린 선은 URL로 공유하지 않습니다.

## 도미넌스 정의와 원천

CoinGecko 무료 API는 초기 조사에서 응답했지만 운영 Worker에서 반복 429가 발생했습니다. 현재는 CoinLore·DefiLlama로 고정하며 자동으로 제공자를 바꿔 시계열을 연결하지 않습니다. 기존 `coingecko` 실패 기록은 보존하되 상태 API에서 `active:false`로 표시합니다.

| 데이터 | 실제 API | 계산·시점 |
|---|---|---|
| 전체 시장 USD 시가총액 | CoinLore `/api/global/`의 `total_mcap` | 별도 원천 기준시각이 없어 조회 시각 표시 |
| 8개 자산·USDT·USDC | CoinLore `/api/ticker/?id=...`의 `market_cap_usd` | 동일 원천 개별 시가총액 / 전체 × 100 |
| 스테이블 전체 ≈ | DefiLlama `stablecoincharts/all` 마지막 일별 관측의 `totalCirculatingUSD` | 모든 USD 환산 필드 합 / CoinLore 전체 × 100. 서로 다른 원천·시점의 근사값 |

DefiLlama의 `totalCirculating`은 네이티브 통화 수량이므로 합산하지 않습니다. 스테이블 전체에 USDT와 USDC가 포함되며 세 항목을 합쳐 100% 차트로 만들지 않습니다. 공급·분류·가격 평가 차이로 CoinGlass·TradingView·CoinGecko 지수와 다릅니다. CoinLore의 응답 조회 시각은 원천 체결 시각 보증이 아닙니다.

`GET /api/v1/dominance`는 `coins`, 전체 시가총액, `source`, `asOf`, `fetchedAt`, `stale`, `calculationVersion`을 반환합니다. 각 코인에 분자 시가총액, 기준 시각, 원천, `timeBasis`가 포함됩니다. `retrieved`는 조회 시각, `daily`는 일별 데이터 기준일입니다. 개별 시장값은 2시간, DefiLlama 일별값은 3일을 초과하면 지연입니다.

`GET /api/v1/dominance/history`는 동일 계산 버전의 최근 최대 1,000회 실제 관측값입니다. 소스가 지연되거나 전체 항목이 빠지면 새로운 정상 이력으로 기록하지 않습니다. 최초 관측 이전의 과거 자료를 생성하지 않으며 관측 시각을 정각으로 소급하지 않습니다. 원본 표본은 D1 `raw_samples`에 원천 URL과 함께 보존합니다.

## 0.3 조회 계약 보완

`overview.quote.change24h`는 숫자 또는 `null`입니다. Upbit의 전일 같은 시각 1분봉이 없거나, 기준보다 5분 이상 오래됐거나, 해당 비교 요청만 실패하면 현재가·거래대금·UTC 당일 고저가는 그대로 검증·제공하고 등락률만 결측으로 반환합니다. `changeUnavailableReason`에 한국어 이유, `referenceAt`에 실제로 확보한 비교 분봉 시각 또는 `null`을 기록합니다. 거래가 없던 구간을 보간하거나 전일 대비로 바꾸지 않습니다.

현재 체결 시각이 5분보다 오래됐거나 미래·비정상 현재가이면 별도의 시세 실패로 처리합니다. 파생 등락률 결측을 현재가 수집 실패와 구분하며, 공개 점검 결과의 `warnings`와 `issues`도 분리합니다. 정상 저장해 둔 시세가 시간이 지나 지연되면 화면의 지연 안내는 유지합니다.

조회 API는 허용한 단일 파라미터만 받으며 모호한 중복, 임의 캐시 분리용 파라미터, 잘못된 수치 범위를 거부합니다. 조회 기본값과 파라미터 순서를 정규화해 같은 요청은 캐시를 공유합니다. 시세는 180초 갱신 잠금과 30초 응답 캐시를 사용하므로 화면에는 정확한 최대치 대신 약 3분 주기와 실제 거래 시각을 표시합니다.
