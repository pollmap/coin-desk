# 0.26 — 시세 재확인과 검색 개선

150개 종목의 기존 분석·저장 구조를 유지하며 시세 재확인, 선물 과거 이력 연결, 검색과 첫 화면 전송량을 보완합니다. [검증 기록](audit-26/README.md)

## 수정 내용

- 실제 체결이 300초보다 오래됐지만 응답 형식은 정상인 경우 `TRADE_STALE`로 구분하고 다음 분에 재확인합니다. HTTP 장애와 잘못된 수치는 기존 재시도 대기를 유지합니다. 실패 횟수·마지막 정상값·성공 시각은 새 정상 관측이 들어오기 전까지 보존합니다.
- VPS에서 최근값만 먼저 가져온 선물 원천은 최초 과거 요청을 가장 오래된 저장 관측 직전부터 시작합니다. 완료 기록이나 기존 과거 원문이 있는 파티션은 다시 시작하지 않습니다. 한 번의 요청·하루 10,000개 과거 후보 제한·저장 공간 보호·최근값 우선 갱신을 유지합니다.
- 시장 검색과 상단 검색은 정확한 티커를 우선하며 Enter로 첫 결과를 엽니다. 한글 조합 중 Enter는 이동시키지 않습니다. 시장 검색 지우기와 Escape는 입력 초점을 보존합니다.
- 시장의 지연 표시는 버튼으로 바뀌었습니다. 열면 마지막 체결, 변동률 기준, 확인 시각을 구분하며 Escape로 닫은 뒤 원래 버튼으로 돌아갑니다. 상세 정보는 열 때만 불러옵니다.
- 보리 원본은 보존하고 32·64·128·192·512px 파생 이미지를 사용합니다. 헤더 전송은 789,844바이트 원본 대신 2,188~6,249바이트입니다. 앱 설치 아이콘도 같은 보리 이미지로 맞추며 앱 ID·주소·저장 키는 유지합니다.

## 데이터 계약

300초 기준은 완화하지 않습니다. 원천에서 체결이 없으면 새 체결 시각을 만들 수 없습니다. ‘수집 재확인 성공’과 ‘최근 체결’, 최근 선물 데이터와 전체 과거 이력은 별개입니다. 과거 이력은 제공 범위와 예약 예산 안에서 이어받으며 완료된 것처럼 표시하지 않습니다.

공개 API 경로·DB 스키마·개인 자료 형식은 유지합니다. 배포 전 복원 검사를 거친 백업을 보관하고 변경된 서비스만 교체합니다. 운영 D1·기존 릴리스·다른 VPS 프로젝트는 보존합니다.

## 검수

300초 경계, 잘못된 수치와 오래된 체결의 구분, 다중 실패 후 다음 분 재확인, 정상 관측 복구, 선물 과거 수집 시작·완료·중복 방지·일일 예산, 검색·모바일 정보창·초점 복귀를 회귀 검사합니다. 전체 계산·서버·복원·Chromium/WebKit 검사는 기존 CI를 유지합니다.

실제 Safari·VoiceOver와 모집 사용자 검사는 별도 미검증입니다. 48시간 대기를 완료 조건으로 다시 추가하지 않습니다.
