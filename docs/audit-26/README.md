# 0.26 검증 기록

현재 소스의 수정과 운영 확인을 분리합니다. 이 문서는 배포 후 증거를 추가합니다.

| 영역 | 배포 전 확인 |
|---|---|
| 타입·계산 | 단위 676개 통과 |
| Node 서버 | 20개 통과 |
| Python VPS | 18개 통과 |
| 신규 검색·정보창 | Chromium/WebKit 4개 통과, 재시도 없음 |
| 전체 원격 CI | 확인 예정 |
| 운영 배포 | 확인 예정 |

모바일 정보창 버튼을 처음 추가했을 때 행 높이가 79.9px로 늘어나는 회귀를 Chromium/WebKit에서 발견했습니다. 상태 버튼은 24px 높이를 유지하고 해당 행의 위아래 간격을 줄여 76px 이하와 초점 복귀·axe를 다시 통과했습니다. 최초 실패를 최종 통과로 합산하지 않습니다.

최근값만 시드로 넣은 선물 파티션에는 과거 커서가 생기지 않던 코드 경로를 수정했습니다. 최근 확보를 전체 과거 확보로 표현하지 않습니다. 기존 원문과 완료 기록이 있는 이력은 재시작하지 않고, 하루 10,000개 과거 후보 제한을 유지합니다.

가격 지연은 원천 거래 부재와 HTTP/검증 실패로 나눕니다. 원천 실제 거래 시각은 바꾸지 않습니다. [업비트 필드 정의](https://docs.upbit.com/kr/reference/list-tickers)에 따라 전일 UTC 대비 등락을 24시간 수익률로 사용하지 않습니다.

성능 비교는 주소별 새 브라우저 문맥 5회, Chromium 153, 1280×800, 다운로드 10Mbps·업로드 5Mbps·추가 지연 0·CPU 1배 조건입니다. 배포 전 일부 표본이 로컬 빌드·검사와 겹쳤으므로 개선 효과의 단독 근거로 사용하지 않습니다. LCP와 실제 가격 준비 시각은 서로 다른 측정입니다. [LCP 측정 구분](https://web.dev/articles/optimize-lcp)

사용자가 작성 중인 별도 기획서와 개인 원본은 이번 변경·커밋에 포함하지 않습니다. 자동 브라우저 검사는 실제 Apple Safari/VoiceOver 또는 사람 대상 사용성 검사를 대체하지 않습니다.

첫 원격 CI `37987068474`는 185개 통과·5개 실패·2개 개인 경로 제외였습니다. 실패는 검색 직후 Enter 1개와 WebKit 768~1440px 시세 버튼의 최소 클릭 영역 4개입니다. 버튼을 전 폭에서 24px로 맞췄습니다. 첫 검색 수정 뒤 반복 검사에서도 12개 중 2개가 실패해, URL 갱신에 따른 입력 초기화를 제거하고 Enter 시 입력값을 직접 읽도록 추가 수정했습니다. 최종 결과는 별도 기록합니다.

[Binance 공식 정의](https://github.com/binance/binance-spot-api-docs/blob/master/rest-api.md#24hr-ticker-price-change-statistics)의 `closeTime`은 통계 종료 시각입니다. 새 시세 정보창은 이를 마지막 체결로 부르지 않습니다. 샘플 조회에서도 동일 거래 ID의 PENGU `closeTime`과 체결 시각 사이에 607ms 차이가 있었고, 이 차이를 0으로 보정하지 않았습니다. 스냅샷의 시각과 실제 스트림 체결 시각은 별개입니다.
