# 가격 전체 이력과 공백 대조

2026-10-14 15:52 KST의 [읽기 감사](history.json)와 15:56 KST의 [시간봉 원천 대조](hourly-gap-check.json)입니다. 공개 사이트에 표시하는 안내문이 아니라 개발·검증 기록입니다.

최초 관측의 원천 증거는 `docs/audit-28/provider-origins.json`에 기록된 2026-10-10 조회를 재사용했습니다. 이번에 384개 공급자 API의 최초 가격을 다시 요청했다는 뜻은 아닙니다. 현재 `/coverage`는 압축 보관 이력과 최근 테이블을 함께 읽습니다. 150개 전체의 모든 과거 가격·OHLC 값을 독립 검산했다는 뜻도 아닙니다.

## 빈 관측의 분류

- 일별 내부 빈칸 334개: Upbit 8종목의 2017년 3일씩 총 24개, FTT Binance 310개입니다. 모두 기존 공식 응답에서 해당 관측이 없었던 증거가 있습니다. 수집 누락이라고 확정하거나 가격을 보간하지 않았습니다.
- 시간봉 내부 빈칸 3,119개 중 3,078개는 기존 원천 응답 대조가 있습니다. 나머지 41개를 현재 실제 시간봉에서 다시 추출했습니다.
- 미확인 41개는 MNT·PENDLE·SPX·COMP·THETA·WIF·XCN·SUPER·GLM·KMNO·KAVA·COW·TFUEL의 Upbit 시간봉입니다. 공식 `candles/minutes/60`을 종목별 1회, `count=200`으로 제한해 확인한 결과 **41개 모두 응답에 관측이 없었습니다.** 복구 가능한 원천 관측은 0개, 429·접근 제한·재시도도 0개였습니다.
- ‘해당 조회 시점에 원천 관측 없음’은 애초 거래가 없었는지, 과거에 제공됐다가 철회됐는지까지 증명하지 않습니다. 실제 수집 실패나 공급자 관측 수정과 혼동하지 않습니다.

위 조사 범위에서 원천에 실제 관측이 있는 누락은 확인되지 않았습니다. 기존 8GiB 공간 보호와 시간봉 90일 정책은 변경하지 않았으며, 과거 수집이나 보간·기존 데이터 삭제를 실행하지 않았습니다.

## 전체 기간의 의미

| 코인 | Upbit KRW 실제 일봉 시작 | Binance USDT 실제 일봉 시작 | Coin Metrics USD 종가 시작 |
|---|---|---|---|
| BTC | 2017-09-25 | 2017-08-17 | 2010-07-18 |
| DOGE | 2021-02-24 | 2019-07-05 | 2014-01-23 |

‘전체’는 선택 원천의 모든 실제 관측입니다. 출시일·전 세계 최초 거래일·거래소 상장일은 같은 날짜가 아닙니다. USD 참조가격은 종가선이며 실제 OHLC처럼 사용하지 않습니다. 슈퍼트렌드는 실제 선택 거래소의 확정 OHLC를 사용하므로 DOGE의 USD 종가를 붙여 2014년부터 캔들을 만들지 않습니다.

가격·슈퍼트렌드·이동평균 리본·볼린저밴드의 새 진입은 전체 기간입니다. 시장·검색의 가격 링크에도 전체를 적용했습니다. 같은 지표를 다시 열거나 명시 URL·기존 저장을 복원하면 사용자의 기간과 확대 구간을 유지하고, 다른 지표를 새로 선택하면 해당 지표의 기본 기간으로 이동합니다.

슈퍼트렌드 최초 9개 준비 봉과 위치 밴드의 앞선 730일에도 **가격은 유지**합니다. 계산 준비기간에 지표선이 없다는 이유로 가격 자체를 자르거나 지표값을 생성하지 않습니다.

## 재현한 조회 결함과 수정

1. 보관 이력에 256개보다 작은 유효 청크가 여러 개 있으면, 고정 청크 수만 읽고 전체 페이지가 끝났다고 판단하던 결함을 격리 SQLite에서 재현했습니다. 시작 커서와 조회 상한을 유지하며 실제 페이지를 채울 때까지 부족 청크를 읽도록 수정했습니다.
2. `history:*` 상태가 없는 기존 가져오기 DB에서는 전체 가격을 반환하면서 `historyStart`를 최근 테이블에서만 구하던 불일치를 재현했습니다. 보관·최근 이력의 최초·끝 관측을 함께 확인하는 읽기 전용 대체 조회로 수정했습니다.
3. 5,801개 격리 일봉의 1,000개 페이지 경계·최근/보관 중복과 4,000개 기초 일봉 경계의 주·월봉을 대조했습니다. 표본 부족, 빈 관측, 오래된 커서로 인해 부분 결과를 완료 처리하지 않게 검사했습니다. 현재 달력 페이지 경계의 추가 결함은 재현되지 않아 페이지 알고리즘을 불필요하게 다시 쓰지 않았습니다.

## 재검사

```powershell
python scripts/audit_price_history.py --checkpoint work/qa-034/history-new.json --report work/qa-034/history-new-report.json
python scripts/audit_price_history.py --hourly-gap-only --report work/qa-034/history-new-report.json --gap-report work/qa-034/hourly-new.json
```

체크포인트는 동일 원천·대상·UTC 관측 종료일·입력 정의 해시에만 재사용합니다. 다른 날짜에는 새 체크포인트를 지정합니다. 실패 대상은 계속 기록하며 `--retry-errors`를 명시할 때만 다시 조회합니다. 공식 원천에서 403·418·429가 나타나면 나머지 원천 조회를 중단합니다. 운영 데이터를 수정하는 기능은 없습니다.
