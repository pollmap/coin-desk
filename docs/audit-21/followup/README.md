# 0.21 VPS 정적 파일 전달 개선

2026-10-03 03:30 UTC에 API만 운영 교체했습니다. [PR #40](https://github.com/pollmap/coin-desk/pull/40)의 CI `37092791650` 통과 후 main `3cc0c807f16e2212ce9d03614118ca441398bd10`에 병합했습니다. 수집기·시세 hub·백업은 같은 컨테이너와 시작 시각을 유지합니다. DB·개인 저장소·강아지 원본은 변경하지 않았습니다.

최종 main CI [37093386222](https://github.com/pollmap/coin-desk/actions/runs/37093386222)도 10분 22초에 통과했습니다. 실행 중이던 `gh run watch`의 완료 로그로 확인했습니다. PR 검사에서 단위 487개·Node 서버 17개·VPS Python 7개·복구 2개·Chromium/WebKit 132개가 통과했고 개인 경로 2개는 제외했습니다. 이후 작업 환경이 네트워크 제한으로 전환돼 GitHub API 재조회는 소켓 권한 오류로 실패했습니다. 이것은 배포된 제품 장애나 CI 실패가 아닙니다. 이 후속 증거 문서만으로 서비스를 다시 배포하지 않습니다.

## 확인한 문제와 수정

[변경 전 실제 VPS 측정](before-browser-performance.json)은 1280×800, 10/5Mbps, 별도 CPU 제한 없음, 새 브라우저 컨텍스트 5개 조건입니다. LCP 5,100/2,220/2,216/3,840/2,212ms로 2.5초 목표를 모두 만족하지 못했습니다. 기존 CDN 주소의 앞선 결과와 구분합니다.

기존 Nginx gzip은 켜져 있었지만 낮은 압축률로 초기 JS 약 131KB·CSS 약 31KB를 전달했습니다. Node 정적 경로에 Brotli/gzip 협상, 내용 기반 ETag·304 재검증, 16MiB·64개 상한 캐시를 구현했습니다. 이미지 픽셀·원본 파일과 UI는 변경하지 않습니다. 재방문 시 같은 789,844바이트 강아지 원본을 다시 전송하지 않습니다. API와 SSE는 정적 캐시에 들어가지 않으며 시장 API의 no-store를 유지합니다.

[HTTP 협상·조건부 요청 기준](https://www.rfc-editor.org/rfc/rfc9110.html#name-accept-encoding)과 [Node 압축 API](https://nodejs.org/docs/latest-v24.x/api/zlib.html)를 사용합니다. 별도 의존성은 추가하지 않았습니다. 압축을 거부한 클라이언트에는 원본을 전달하며 허용 표현이 없으면 406을 반환합니다. HTML 원천 주소 변경도 ETag에 포함하고, 파일 변경 시 이전 내용을 재사용하지 않습니다.

로컬 Node 서버 17개·VPS Python 7개 통과. 압축 해제 내용 일치, 압축 q=0, 304, 파일 변경·캐시 퇴출, 주소별 HTML, 원본 이미지 보존을 검사했습니다. 후보 VPS 읽기 API 29개도 통과했습니다. [실제 빌드별 크기](static-sizes.json)에는 기존 배포에서 보존한 옛 자산도 포함하므로 현재 파일명을 대조합니다.

## 운영 지속성

[전환 후 6시간 30분 원장](partial-operation.json): 네 수집 작업 모두 예상 390회·기록 390회·성공 390회, 오류·겹침 없음, 최대 실제/예약 간격 60초. 이 부분 구간은 **완전 UTC 하루나 보존된 48시간 창의 대체 증거가 아닙니다**. 앞선 전환 공백 2,700초를 삭제하지 않습니다.

[현재 상태](before-status.json)에서 활성 원천 103개 정상, 네 실행부·백업 정상, 미해결 분석 지연 없음. 2026-10-03 09:10 KST 브리핑 생성도 확인했습니다. 기존 48시간 ready=false는 유지합니다. 첫 운영 하루·다음 백업·디스크/로그 증가량 확인과 전체 계획의 기타 미검증 범위는 [릴리스 문서](../../RELEASE21.md)를 따릅니다.

원장 점검의 첫 SQL은 daily_briefings에 없는 date 열을 사용해 실패했습니다. 스키마의 실제 id·created_at 열로 바로잡은 SELECT 결과만 증거로 사용했습니다. 운영 데이터는 변경하지 않았습니다.

## 변경 서비스만 배포

Compose의 API 이미지·릴리스에 별도 선택값을 추가했습니다. 기존 전역 이미지·릴리스는 유지하고 API 선택값만 새 릴리스로 지정합니다. 교체 전후 나머지 서비스 구성과 컨테이너 ID·시작 시각을 대조합니다. API 교체 실패 시 이전 API 이미지로 복구하며 DB를 되돌리지 않습니다. 새 정적 파일 전달 때문에 이미 실행 중인 분 단위 수집을 다시 시작하지 않습니다.

- API와 `current`: `vps-d1307aabbe7ab4ec`. 수집기·hub·백업: `vps-f1546991c2aab31a` 유지.
- [교체 결과](api-upgrade-result.json): 다른 6개 프로젝트 컨테이너 동일, Nginx·DB 변경 없음. 검사 후 임시 후보 API만 제거했습니다.
- [배포 후 읽기 검사](deployment-summary.json): 29개 API HTTP 200, health 정상, 활성 원천 103/103 정상, 원천 미해결 오류 없음. [공개 API와 읽기 전용 DB 원자료](api-upgrade.json).
- [실제 HTTP 응답](static-protocol.json): 초기 JS 원본 345,874바이트, gzip 113,294바이트, Brotli 107,460바이트. 압축 해제 SHA-256 일치. 기존 gzip 전송 131,226바이트 대비 Brotli 약 18% 감소입니다. 강아지 재검증은 304·본문 0바이트이며 시장 API는 `no-store`입니다.

## 속도 결과와 남은 조건

[같은 조건의 변경 후 측정](after-browser-performance.json): LCP 4,992/2,248/2,244/2,224/2,188ms, p95 4,992ms입니다. **VPS 직접 주소의 LCP 2.5초 목표는 아직 미달**입니다. 중앙값은 2,220→2,244ms로 개선되지 않았으며, 전송량 감소를 전체 로딩 속도 개선으로 과장하지 않습니다. [전후 Navigation Timing](navigation-timing.json)에서 첫 측정은 모두 DNS 조회 시작 전 약 2.7초를 포함합니다. 이 지연의 원인은 확정하지 않았습니다. 기존 Pages CDN 주소의 앞선 p95 1,004ms는 별도 주소의 결과입니다.

실제 가격 변경 26건에서 브라우저 수신→화면 p95 26.2ms, 서버 수신→화면 p95 1,165.5ms, 시계 오차 포함 상한 1,376ms로 3초 목표를 만족했습니다. 소규모 관찰 표본이며 항상 보장되는 지연은 아닙니다. [실제 운영 화면](after-market-1280.png)에서 여덟 코인과 기존 강아지를 확인했습니다.

관찰 이력을 초기화하지 않아 엄격한 48시간 판정은 여전히 false입니다. 수집기 전환 이후 첫 완전 UTC 하루인 10월 3일의 결과는 10월 4일 01:00 UTC 이후, 48시간은 가장 빨라도 10월 4일 20:50 UTC 이후 확인합니다. 이번 API 패치 이후 첫 완전 UTC 하루는 10월 4일이며 10월 5일 01:00 UTC 이후 별도 확인합니다. 화면·코드 배포 완료와 장기 운영 통과를 구분합니다.
