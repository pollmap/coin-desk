## 첫 전환 시도 및 복구

2026-10-02 20:06~20:12 UTC 사이 기존 주소 API 중계에서 503을 관측했습니다. VPS 직접 API는 HTTP 200이었습니다. 기존 Worker `ec112aab-c88f-483e-a8d5-14b6d766fe68`로 되돌리고 `btc-desk`·`btc-desk-quotes` 매분 Cron을 복원한 뒤 기존 주소 status HTTP 200을 확인했습니다. 정확한 사용자별 장애 시작/종료와 영향 요청 수는 확정하지 않았습니다. 데이터 삭제나 최종 DB 전환은 하지 않았습니다.

원인은 gateway의 `redirect: error`입니다. workerd가 이 옵션을 허용하지 않아 외부 요청 전에 예외가 발생했습니다. 처음 확인한 request-signal 설정은 원인으로 확정하지 않았으며 실제 엔진 재현으로 바로잡았습니다. `manual` 모드로 읽고 3xx를 명시적으로 거부하여 다른 목적지나 인증정보 전달을 막습니다. 실제 workerd에서 정상 요청·자격증명 제거·301/302/303/307/308 거부를 확인하는 회귀 검사를 추가했습니다. 기존 Node 단위검사가 Cloudflare 런타임 차이를 잡지 못한 범위를 기록합니다.

PR #37 squash 커밋 본문에 과거 문서 커밋의 skip-ci 표시가 포함되어 main 자동 CI가 생기지 않았습니다. main 정확한 커밋 대상으로 CI `37058582230`을 수동 실행했습니다. 해당 실행은 최종 통과했고, PR #38 main CI `37060472575`도 통과했습니다.
