# 후속 결함 수정·운영 점검

2026-10-03 UTC. 이 기록은 [PR #41 배포](../closeout/deployment/README.md) 이후 점검입니다. 사용자 요청으로 48시간 대기·합격 조건은 폐지했습니다. 현재 정상 여부와 과거 실행 이력은 구분하며 이력을 삭제하지 않았습니다.

## 수정한 결함

- 키보드 Home·날짜 이동으로 보이는 구간 밖의 관측을 선택한 뒤 창 크기가 바뀌면 기본 기간으로 돌아가던 문제를 수정했습니다. 실제 사용자가 이동한 범위를 기억합니다. 수정 전 Chromium/WebKit 2개가 실패했고 수정 후 관련 8개와 핵심 두 흐름 20회 반복 검사를 재시도 없이 통과했습니다.
- 앞선 문서 커밋의 [CI 37107204819](https://github.com/pollmap/coin-desk/actions/runs/37107204819)는 WebKit 최근값 복귀 검사 1개가 실패했습니다. 원래 검사는 로컬 10회에서 재현되지 않았습니다. 선택 날짜 문구가 바뀐 시점과 실제 차트 이동 완료 시점이 다른데 이전 프레임의 구간을 읽는 검사 문제를 고쳤습니다. 별도로 재현한 위 제품 결함과 동일 원인이라고 단정하지 않습니다.
- 선물 API의 잘못된 입력 안내가 BTC·DOGE·ETH만 지원하는 것처럼 말하던 문구를 수정했습니다. 실제 여덟 코인 지원 범위나 단위·수집 조건은 변경하지 않았습니다.
- Nginx 복구 도구가 API upstream 하나만 기대해 현재 API·SSE 두 경로 설정에서 실패하던 문제를 수정했습니다. 두 경로를 같이 변경하고 서로 다른 포트·외부 upstream·예상 외 설정은 거부합니다. 이전 릴리스로 이동한 뒤에도 이번에 검증한 복구 도구를 사용합니다.
- 읽기 전용 운영 보고 도구를 추가했습니다. 완전 UTC 하루와 부분 구간, 예약 누락·오류, 브리핑·백업·저장 용량을 구분합니다. 부분 구간을 하루 비용이나 용량 증가로 환산하지 않습니다.

## 전송 설정과 성능 판단

Nginx 설정 파일에 명시적인 HTTP/2 표시가 없었지만 실제 ALPN은 수정 전부터 `h2`였습니다. 잠시 명시 설정을 적용했을 때 공유 443 listener의 protocol 경고가 나왔습니다. 성능 이득도 입증하지 못해 **Coin Desk 설정을 원래 파일과 바이트 단위로 일치하도록 복원**했습니다. `nginx -t`가 통과했고 `h2`는 계속 동작합니다. 다른 프로젝트 설정은 수정하지 않았습니다. HTTP/2를 새로 켜서 속도가 개선됐다고 표현하지 않습니다.

시세 요청의 우선순위를 높이는 브라우저 실험도 일관된 개선이 없어 제품에 넣지 않았습니다. 직접 주소 첫 로딩의 DNS 이전 지연이 일부 표본에서 있었지만 원인은 확정하지 않았습니다. CDN을 사용하는 기존 Pages 주소를 주 접속 주소로 유지합니다. VPS에는 실제 API·데이터·수집기가 있으며 Pages가 별도 모의 데이터를 제공하는 구조가 아닙니다.

배포 전 동일 조건의 표본은 [Pages 성능](performance-edge-before.json), [VPS 직접 성능](performance-direct-before.json)에 기록합니다. 1280×800, 다운로드 10Mbps·업로드 5Mbps, 추가 지연 0, CPU 배속 1, Chromium 153, 새 컨텍스트 5개·같은 브라우저 프로세스입니다. Pages LCP p95 576ms, VPS 직접 주소 5,956ms입니다. **작은 표본이며 직접 주소의 2.5초 목표는 아직 달성하지 못했습니다.** 전체 여덟 가격 표시까지의 별도 3회 표본은 [가격 준비 시간](market-readiness.json)이며 LCP나 장기 p95로 부르지 않습니다.

실제 [SSE 100명·30초 검사](sse-100.json)는 모두 연결됐고 오류 0, 최소 이벤트 31개, 수신 표본 5,329개, 서버 수신부터 클라이언트 수신까지 p95 931ms입니다. 같은 VPS에서 실행해 시계 차이는 없지만 브라우저 그리기는 제외합니다. 새 체결은 Binance 8종·Upbit 6종에서 관측됐습니다. 짧은 구간에 새 체결이 없던 Upbit ONDO·PEPE까지 갱신됐다고 집계하지 않습니다.

최종 배포 후 다른 파일 다운로드가 끝난 상태에서 동일 조건으로 다시 측정했습니다. [Pages 결과](performance-edge-after.json)와 [VPS 직접 결과](performance-direct-after.json)는 다음과 같습니다.

| 항목 | Pages | VPS 직접 주소 |
|---|---:|---:|
| LCP 5개 표본(ms) | 380, 376, 408, 364, 412 | 2,320, 2,300, 2,128, 2,224, 2,224 |
| LCP p95(ms) | 412 | 2,320 |
| 실제 가격 변경 표본 | 19 | 8 |
| 브라우저 수신→화면 반영 p95(ms) | 17.2 | 16.6 |
| 서버 수신→화면 반영 p95, 시계 오차 포함 상한(ms) | 1,303 | 1,310 |

이번 5회 표본은 목표 안입니다. 그러나 앞선 직접 주소 5,956ms 표본과 최초 브라우저 종료가 있었으며, 이번 차트 수정이 네트워크 지연을 고친 변경은 아닙니다. 새 컨텍스트는 사용했지만 OS·DNS·TLS의 모든 캐시를 지운 측정도 아닙니다. **처음 접속할 때마다 2.5초 이내라고 보장하거나 지연 원인을 해결했다고 결론내리지 않습니다.** 별도 실행 성능 2개는 자동 재시도 없이 통과했습니다.

## 검증 범위와 한계

[PR #42](https://github.com/pollmap/coin-desk/pull/42)는 운영 도구, [PR #43](https://github.com/pollmap/coin-desk/pull/43)은 차트·오류 문구 수정입니다. 코드 main은 `8dc3a096a5ede526afe1697553ae725c105a5e2a`, VPS API는 `vps-7e72771fa7feac35`, Pages는 [bfd4bcd0](https://bfd4bcd0.coin-desk.pages.dev)입니다. [검증 요약](verification.json)에 PR·main CI를 구분해 기록합니다. 단위 487개, 복구 2개, Node 서버 17개, VPS Python 15개, Chromium/WebKit 144개이며 개인 경로 opt-in 2개 제외·브라우저 재시도 0입니다.

[API 배포](api-deployment.json)는 API 하나만 교체했고 수집기 4개·시세 hub·백업 6개 서비스의 컨테이너 ID·시작 시각을 보존했습니다. DB 복원·추가 마이그레이션은 없습니다. [정적 파일 대조](deployment-assets.json)는 양 주소의 파일 각각 189개가 빌드와 일치합니다. 이전 릴리스의 해시 자산을 유지합니다. Pages 배포 때의 dirty 경고는 작성 중인 감사 문서 변경에 대한 것이며 제품 소스는 병합한 코드와 일치합니다.

[실제 UI 검사](production-ux.json)는 여덟 코인 이동, ONDO 미지원 MVRV 안내, 양 테마 axe, 차트 상단 240px 이내·높이 420px 이상을 확인했습니다. [날짜 탐색 검사](production-keyboard.json)는 두 운영 주소에서 2010-07-18로 키보드 이동한 후 화면 크기 변경과 최근값 복귀에도 표시 기간을 유지했습니다.

[실제 읽기 API](connected-data.json) 28개가 HTTP 200이고, 가격 8개·선물 8개·MVRV 5개·ETH TVL 1개의 이력 22개가 비어 있지 않습니다. MVRV 미확보인 SOL·ONDO·PEPE에 다른 코인의 값을 넣지 않습니다. 후보 API 검사 첫 시도는 health 503으로 중단됐고 상세 응답을 확보하지 못했습니다. 이어서 원천 정상·health 200을 확인한 뒤 동일 후보 29개 검사가 통과했습니다. [재검사 기록](candidate-recheck.json)의 첫 실패 원인을 특정 코인으로 단정하지 않으며 기준을 낮추거나 수집기를 재시작하지 않았습니다.

[최종 상태](final-status.json)는 08:58 UTC 활성 원천 103/103 정상·health 200입니다. 비활성 원천을 정상 개수에 더하지 않습니다. 이 최종 정상 상태는 위 일시적 503이나 과거 누락이 없었다는 뜻이 아닙니다.

[자연 갱신](natural-progress.json)은 08:50:04–08:55:04 UTC 300초 표본입니다. 핵심 코인 양 거래소 시세 6개의 실제 체결·확인 시각과 선물 확인 12개가 증가했습니다. 구간 안에서 완료된 수집은 quotes 4회, 다른 세 작업 각각 5회입니다. 마지막 실행이 완료되기 전 읽은 경계를 하루 누락으로 해석하지 않습니다. 직접 수집·overview 호출이 없었고 다른 방문자가 없었다고 보장하지 않습니다.

[UTC 운영 집계](operations.json)는 00:00–08:52 UTC의 **부분 구간**으로 네 작업 각각 532/532회 성공입니다. 실제·예약 최장 공백 60초, 브리핑 `2026-10-03`, 검증 백업 정상·신선도를 확인했습니다. DB·WAL·SHM 합계 42,852,192바이트, 백업 191,950,609바이트입니다. 이전 보고서 이후 2,658초 동안 DB 합계 +4,096바이트·백업 +0바이트이며 하루 증가량이나 서버 전체 디스크 사용량은 아닙니다.

최초 운영 브라우저 검사 묶음에서는 Pages 성능 측정 중 `browserContext.newPage: Target crashed`가 발생했습니다. 제품 화면 검사 2개는 통과했고, 성능은 파일 다운로드와 겹치지 않는 별도 실행으로 다시 측정했습니다. 첫 직접 주소 표본은 배포 파일 다운로드와 겹쳐 최종 성능 비교에서 제외했습니다. 오류를 숨기거나 자동 재시도로 성공 개수에 포함하지 않습니다.

- 스키마 0009, 기존 DB·개인 자료·시바견을 유지합니다. Cloudflare 수집기는 재활성화하지 않습니다.
