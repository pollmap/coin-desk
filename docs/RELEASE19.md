# Coin Desk 0.19 — 기존 분석을 이해할 수 있는 사전

웹 0.19.0입니다. 서버 0.17.1·Chrome 확장 0.18.0은 변경하지 않습니다. X 추가 수집보다 기존 기능의 설명·사용 흐름을 먼저 보완하라는 최신 요청을 반영했습니다.

## 수정한 문제

- 사전 첫 화면의 추천 항목이 설명을 건너뛰고 차트로 이동했습니다. 이제 모든 추천·이어 읽기는 설명 글로 연결됩니다. 지표 화면의 ‘읽는 방법’에서도 관련 설명으로 이동합니다.
- 상세 글의 기본 모드는 산식을 접고 있었고, 가격 위치 밴드에는 공식 대신 소개 한 줄만 있었습니다. 산식·기호·가상 숫자 예시를 기본으로 노출합니다. 예전 읽기 모드 설정이 남아 있어도 설명을 숨기지 않습니다.
- 도움말 상단에 코인·가격 기준 조작과 차트 적용 패널이 반복됐습니다. 읽는 화면에서는 이를 제거하고 글 끝의 명시적인 ‘차트에서 확인하기’에 모았습니다. 글을 읽는 동안 가격 시계열·지표 지원 범위를 조회하지 않습니다.
- 목록을 일곱 분류로 묶고, 상세 글에 목차를 추가했습니다. 관련 설명을 열면 제목으로 이동하며 키보드 포커스도 따라갑니다. 빈번한 검색·즐겨찾기·기존 코인·원천·날짜 전달은 유지합니다.
- 확대하거나 읽기 영역이 좁아지면 목차를 글 위로 옮기고, 기호 설명과 선택 도구를 세로로 재배치합니다. 화면 전체 너비만으로 판정해 200% 확대에서 글이 넘치던 문제를 CI에서 발견하고 수정했습니다.
- 관련 글로 이동했을 때 공통 페이지 전환이 제목의 초점을 빼앗던 충돌을 수정했습니다. 글 끝에서 적용할 코인을 바꾸는 동안에는 제목으로 튀어 올라가지 않고 선택 도구를 그대로 사용할 수 있습니다.
- 관련 글에서 뒤로 가면 이전 URL의 목차 단락으로 스크롤과 초점을 복원합니다. 새 글의 제목 이동과 읽던 위치의 복귀를 구분합니다.
- 작업공간·개인 자료함·데이터 상태 설명은 해당 화면으로 바로 연결하며, 필요 없는 코인·통화 선택을 요구하지 않습니다.

## 70개 설명의 보완

모든 기존 항목에 **질문 → 의미 → 계산식 또는 사용 방법 → 예시 → 데이터 범위 → 해석의 한계**를 제공합니다. 사용 도구에는 존재하지 않는 금융 산식을 붙이지 않고 조작·저장 범위를 설명합니다.

가격 위치 밴드는 직전 730일 로그 종가의 평균 μ, 모집단 표준편차 σ, `exp(μ + kσ)` 경계와 위치 점수 `(ln(P) − μ) / σ`를 설명합니다. 오늘 가격을 밴드 표본에서 제외하고, 첫 731번째 관측부터 표시하며, 결측 이후에는 표본을 다시 쌓는 실제 구현과 맞췄습니다. 중심 100·로그 표준편차 0.2·오늘 120의 예를 독립 입력으로 계산해 +0.91σ와 111.63/129.69 경계를 확인했습니다.

리본·SMA/EMA·RSI·볼린저·MACD·365일 VWAP·낙폭·상대강도·상관·계절성·사이클의 계산 기준과 예시를 보강했습니다. 온체인은 원천 값과 역산 값을, 선물은 기초 코인 수량·계정 비중·정산률을 구분합니다. 패턴은 공개된 형태 규칙과 설명용 OHLC를 함께 보여 줍니다. 원천을 재계산하지 않는 집계는 직접 검산한 산식으로 표현하지 않습니다.

## 실제 계산 오류

직전 730일 가격이 모두 같으면 표준화 위치는 정의되지 않습니다. 기존 구현은 0 또는 부동소수점 소거 오차로 큰 점수를 만들 수 있었습니다. 같은 값의 수를 관리해 정확히 0인 변동 폭을 식별하고 위치 점수를 `null`로 유지합니다. UI는 ‘변동 폭 없음’으로 설명하며 ‘중앙’이나 투자 신호로 표시하지 않습니다. 가격선과 밴드 중심 값은 보존합니다.

## 검증과 배포

[검증 기록](audit-19/README.md)에 검사 결과·실패·CI·운영 확인을 기록합니다. 사전 70개 모두 브라우저에서 실제 렌더링하고, 읽기 중 차트 미생성·시계열 미요청, 도움말에서 차트로 명시적 전환, 원천·단위 유지, 320/390/768/1000/1280/1440px·양 테마·키보드·200% 확대·axe를 확인합니다.

기존 서버 Cron·스키마·데이터는 변경하지 않습니다. 서버의 48시간 안정성 및 2026-09-28 완전 UTC 하루 비용 검증 창은 유지합니다. Apple 기기가 없어 실제 Safari·VoiceOver는 미검증입니다. 개인 X 자료 수집·전수 내용 검토를 이번 수정의 완료 성과로 세지 않습니다.

## 0.19.1 — 늦게 실행된 Cron의 실제 공백 표시

2026-09-29 운영 후속 검사에서 9월 28일 20:40:37–20:46:30 UTC 사이 실제 실행 공백 353초를 확인했습니다. 늦게 도착한 작업이 이전 예약 분에 기록되면서 기존 상태 판정은 예약 간격 180초만 표시했습니다. 수집 재개를 과거 공백이 없었던 것으로 해석할 수 있는 오류였습니다.

예약 기록률·누락·성공률은 기존 기준을 유지하고, `longestStartGapSeconds`와 `longestScheduledGapSeconds`를 추가합니다. 기존 `longestGapSeconds`에는 두 값 중 큰 값을 사용합니다. 관찰 창의 앞뒤와 최근 2분 유예도 구분합니다. 기록률 99%·최장 공백 180초·미해결 오류 없음 기준과 기존 기록을 그대로 유지하며, 상태 화면에서 실제 실행과 예약 기록의 간격을 함께 설명합니다.

이 패치는 상태 판정·표시만 수정합니다. 원천 수집 로직·매분 예약·예산 제한·기존 스키마·개인 자료는 변경하지 않습니다. 실행 지연 및 별도로 관측된 일봉 작업 중단 1건의 원인은 확정하지 않았습니다.

9월 28일 공식 계정 전체 사용량은 읽기 4,011,199행·쓰기 63,397행으로 무료 한도 안이었습니다. 다음 날 브리핑도 생성됐지만 실제 공백이 남아 있어 운영 마감을 완료로 처리하지 않습니다. [하루 집계와 실행 기록](audit-19/heartbeat-20260929-0104.json). 타입·단위 468개와 상태 화면의 로컬 WebKit 회귀 검사는 통과했으며, CI·병합·배포 검증은 [감사 기록](audit-19/README.md)에 이어서 기록합니다.
