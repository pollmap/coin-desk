# 보리차트 0.23 — 시장·테마와 지표의 연결

## 목적과 사용자 흐름

주요 여덟 코인의 성격과 상태를 살펴본 뒤, 해당 코인에서 지원하는 지표를 찾아 날짜별 값을 확인하고 저장합니다. 시장 전체를 대표하는 테마 지수나 투자 추천을 만들지 않습니다.

`시장 전체·관심·테마 → 코인 → 목적에 맞는 지표 → 날짜 고정·설명 → 분석 저장 → 다시 열기`

기존 React·Lightweight Charts·Node·SQLite와 독립 수집기를 유지합니다. 새 DB, 거래소, 유료 데이터, 벡터 검색, 주문 또는 X 수집을 추가하지 않습니다. 기존 주소·저장 키·작업공간 버전 1·2·개인 자료·백업 형식을 보존합니다.

## 화면 명세

| 화면 | 주요 행동 | 데이터·상태 |
|---|---|---|
| 시장 | 전체·관심·테마 전환, 코인·분석 선택 | 최초 시장 일괄 조회와 SSE 유지. 갱신마다 정렬하지 않고 ‘지금 값으로 정렬’ 제공 |
| 테마 | 분류 근거 확인 → 해당 코인 분석 | 5개 편집 분류, 복수 분류, 추적 종목 수. 화면을 열 때 읽기 API 요청 |
| 상세 | 목적 검색, 자주 보는 지표, 상단 저장 | 지원 목록과 실제 관측 상태 구분. 다른 코인의 데이터로 대체하지 않음 |
| 차트 | 기간·날짜·구간 확대·가격 비교·전체화면 | 임시 확인과 클릭·키보드 날짜 고정 구분. 최근값 복귀. 자동 갱신·설명 변경에도 범위 유지 |
| 설명 | 현재 확인 날짜·값과 기준선 의미 확인 | 공식·예시·출처·한계는 기존 공통 정의 사용. 사전은 설명 전용 |
| 비교 | 현재 설정 한 줄 확인 → 필요할 때 펼치기 | 같은 원천·통화·공통 관측, 아래 결과 표 유지 |
| 관계 | 목록 또는 고정 배치 지도 → 근거 → 지표 | 처음 최대 12노드, 실제 카탈로그는 더 작음. 관계 이름과 근거 표시. 지도만 별도 지연 로드 |
| 내 저장 | 이름·코인·지표·원천·기간 확인 | 덮어쓰기 확인·삭제 취소·백업 복원 유지 |

## 디자인 규칙

흰색 `#FFFFFF`, 보조 표면 `#F5F6F8`, 본문 `#202633`, 보조 글자 `#596579`, 청록 `#0F666B`를 사용합니다. 저장한 다크 테마는 유지합니다. 표·행·구분선과 큰 차트가 중심이며 보리는 기존 브랜드 위치에만 둡니다.

버튼 위치와 크기는 변하지 않습니다. 테두리 150ms와 대화상자 투명도 150ms를 사용하고 움직임 줄이기에서 제거합니다. 테마 전환 중 글자와 배경의 대비가 잠깐 무너지는 배경색 보간은 제거했습니다. 차트의 데이터 색상 구간은 장식 그라데이션과 구분합니다.

Base UI로 지표 선택·날짜·저장·관계 대화상자와 날짜 도구 팝오버의 Escape, 초점 복귀를 통일했습니다. 해당 화면의 기존 native dialog 규칙을 제거했습니다. 기존 고급 분석의 스타일과 경로는 보존했으며 전역 CSS를 모두 재작성했다고 주장하지 않습니다.

개발용 Storybook은 정상·지연·미지원·이력 부족·수집 대기·로딩·오류 상태를 동일 컴포넌트로 확인합니다. `npm run storybook` 또는 `npm run build:storybook`으로 실행합니다. Storybook은 공개 서비스에 배포하지 않습니다.

## 관계·검색 모델

버전 관리되는 [관계 카탈로그](../shared/knowledge.ts)는 자산, 프로젝트, 네트워크, 테마, 지표, 제공자를 구분합니다. 모든 노드·관계에 근거 URL, 제공자, 확인일, 검토 상태, 공식 설명/편집 분류/구현 정의 구분을 둡니다.

- `GET /api/v1/themes`: 검토한 5개 분류와 추적 코인.
- `GET /api/v1/knowledge?asset=ONDO`: 선택 자산의 직접 관계와 근거.
- DB 쓰기 없는 API이며 지원하지 않는 자산·추가 파라미터는 거부합니다.
- ONDO는 거버넌스 토큰이며 국채나 이자 청구권으로 표현하지 않습니다.
- LINK·PEPE의 Ethereum 연결은 확인한 발행 네트워크이며 전체 체인 배포 목록이 아닙니다.
- 상관관계는 사업 관계·인과관계로 연결하지 않습니다.
- 검색은 기존 이름·한글·티커와 지표 이름·짧은 뜻·사용 목적 별칭을 사용합니다. 임베딩과 GraphRAG는 도입하지 않았습니다.

## 데이터·운영 변경

VPS 배경 수집은 재시도 기한이 지난 작업 중 실제 대기 시점이 오래된 작업을 선택합니다. 과거 날짜가 계속 동일한 작업도 시도 후 순서를 양보합니다. 공급자 backoff는 우회하지 않습니다. 시세·최근 주요 선물의 독립 실행 경로는 유지합니다.

최신 가격 봉은 먼저 요청하고 과거 결측 구간은 별도 체크포인트로 한 페이지씩 복구합니다. 과거 요청 실패가 검증된 최신 응답을 버리지 않게 하며, 데이터 상태 화면에서 복구 중인 범위와 재시도를 따로 표시합니다. 결측을 보간하지 않습니다.

SQLite가 스스로 트랜잭션을 종료한 경우 추가 rollback 실패가 원래 오류를 덮어쓰지 않도록 했습니다. 공개 오류 코드에는 저장 공간, 잠금, 원천 수정, 요청 제한, 시간 초과를 구분합니다. 요청 헤더·인증정보·개인 자료는 노출하지 않습니다.

백업은 초기 상태 파일 작성 실패도 처리하고 원자적으로 상태 파일을 교체합니다. 저장 공간 오류 등 안전한 코드만 기록하며 기존 검증된 백업을 보존합니다. 현재 백업과 복원 검사는 같은 VPS 범위이며 외부 재해복구 완료를 의미하지 않습니다.

ETH 10월 7일 관측 회복은 이번 배포 전에 확인됐습니다. 새 코드 효과로 소급하지 않습니다. 과거 rollback 오류의 최초 원인과 디스크 상태 변화의 원인은 확정하지 않았습니다. 관측된 사실과 재현한 결함을 구분합니다.

## 검증과 완료 범위

[감사 기록](audit-23/README.md), [실제 보유 이력](audit-23/DATA_SUPPORT.md), [발견 사항](audit-23/FINDINGS.md)을 함께 확인합니다. 타입·계산·저장 복구·API·브라우저 검사, 원격 CI, 운영 배포 증거를 구분합니다. 현재 진행 상태는 감사 기록이 기준입니다.

48시간 대기를 다시 넣지 않습니다. 기존 예약 갱신·과거 실행 기록·300초 시세 유효성은 유지합니다. 실제 Safari·VoiceOver, 사람 5명의 이해도 과제는 자동 검사로 대체하지 않습니다. 실제 사용자 모집 전에는 미검증입니다.

사용성 과제는 ① ONDO를 테마에서 찾기 ② MVRV의 관측일과 현재 가격 시각 구분 ③ 두 코인 비교 원천 확인 ④ 날짜를 고정하고 의미 확인 ⑤ 저장 후 다시 열기입니다. 첫 사용자 5명에 대해 도움 없이 완료한 과제 수/5, 소요 시간, 막힌 위치를 기록합니다. 아직 사람의 성공률 수치는 없습니다.

## 출시·복구

검증된 PR의 main 병합 후 변경된 API·배경 수집·SQLite 어댑터를 사용하는 수집기·백업만 갱신합니다. 시세 허브, DB 스키마, TLS·Nginx와 다른 서비스는 유지합니다. readonly 후보 API와 실제 데이터 확인 후 전환하며 이전 이미지·릴리스·정적 자산·DB 백업을 유지합니다. Pages는 동일 웹 빌드를 배포하고 실제 API는 기존 VPS 프록시를 사용합니다.
