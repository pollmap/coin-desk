# 연구 보고서의 첫 배포

연구 작업자는 기존 시세·수집 작업과 별도 서비스다. 같은 CI 이미지로 API와 연구 작업자만 교체하며, 작업자는 비활성 상태로 먼저 배포한다. 기존 네 수집 lane, 180초 상태 기준, 시세 허브와 백업 서비스는 교체하지 않는다.

## 검증 순서

1. main의 다섯 CI 작업과 공식 이미지·소스 아카이브 SHA를 확인한다. 현재 릴리스, 기존 8개 컨테이너, 디스크 8GiB 여유와 실행 메모리를 다시 확인한다.
2. `research_schema.make_plan(connection, migration_path)`로 현재 읽기 전용 DB의 정확한 21개 테이블·전체 스키마와 새 `0010_research_reports.sql`의 해시를 고정한다. 파일 바이트 해시와 Node 마이그레이션 장부의 정규화된 해시를 각각 보관한다.
3. 검토한 번들의 `deploymentKind`를 `research-additive-v1`, `changedServices`를 `['api', 'research-worker']`로 지정한다. `schemaPlan`에 위 계획을 포함하고 기존 배포 도구 네 파일에 `research_release.py`, `research_schema.py`의 SHA를 추가한다. 다른 배포에 이 계약을 암묵적으로 적용하지 않는다.
4. `scripts/deploy_vps.py stage-prepare --bundle <검토한 번들> --execute`로 새 백업과 독립 복원본을 만든다. 복원본에만 0010을 적용하고 기존 20개 데이터 테이블의 행 수·내용 해시, 장부의 기존 행, 정확한 6개 새 테이블·3개 인덱스·2개 트리거를 대조한다. 새 27개 테이블도 별도 백업·독립 복원으로 확인한다.
5. 새 API를 복제 DB에서 확인한다. 연구 작업자는 네트워크 없는 컨테이너에서 비활성 `--once`·`--health`를 검사하고, 읽기 전용 DB 마운트에서 `--dry-run`을 검사한다. 구 이미지가 새 스키마의 기존 데이터와 네 수집 lane을 읽는지도 확인한다.
6. `activate --bundle <검토한 번들> --execute`는 1시간 이내 백업과 봉인된 입력을 재확인한다. 운영 DDL은 쓰기 잠금 대기 1초·트랜잭션 5초 이내이며 기존 데이터 쓰기를 차단한다. 새 장부 1행만 허용한다. 새 스키마의 운영 백업·독립 복원 후 API와 비활성 연구 작업자만 시작한다.
7. 별도 승인된 `enable-research --bundle <검토한 번들> --execute`에서 현재 릴리스·실제 이미지·새 스키마·복원 백업·비활성 검사를 재대조한다. 환경 설정은 연구 활성 플래그 하나만 바꾸고 연구 컨테이너만 재생성한다. 기존 8개 컨테이너 ID, 네 수집 lane과 핵심 시세 6개의 자연 진행을 확인한다.

배포·활성화는 기본적으로 실행하지 않는다. `--execute` 없는 명령은 번들 검증만 한다. 원격 명령, 환경 설정, 상세 스냅샷은 비공개 감사 폴더에 보관하며 공개 문서에는 인증정보나 내부 경로를 넣지 않는다.

## 실행 범위

- 연구 컨테이너: 최대 0.5 CPU·512MiB, 포트 없음, 별도 `research` 프로필, 자동 마이그레이션 없음.
- 수집 상한: 실행 600초, 시장 총 10개 이내이며 현물·파생 각각 최대 5개. 제공자별 제한은 연구 수집기가 적용한다.
- 일정: 매일 09:10 KST에 전체 시장·Injective 순서로 처리하고, 주간 보고서는 월요일 09:20 KST에 처리한다.
- 연구 heartbeat는 신규 연구 테이블에만 저장한다. 연구 상태 검사와 기존 시세·수집 상태 검사를 구분한다.
- 과거 복구의 만료된 승인이나 예산은 이 배포로 재개·초기화하지 않는다.

## 실패와 복구

마이그레이션 전 실패하면 기존 서비스를 바꾸지 않는다. DDL 실패는 해당 트랜잭션을 되돌린다. DDL 성공 후 API·연구 작업자 검사가 실패하면 연구 작업자만 중지하고 API를 기존 이미지로 되돌린다. 추가된 연구 테이블은 유지하며 운영 DB를 과거 백업으로 덮어쓰지 않는다.

연구 활성화에 실패하면 연구 플래그를 0으로 복원하고 해당 작업자만 비활성 상태로 재생성한다. 재생성도 실패하면 검증된 해당 연구 컨테이너만 중지한다. 게시된 보고서·관측·시장 데이터는 삭제하지 않는다. 실패 증거가 있으면 동일 단계의 자동 재실행을 하지 않고 현재 상태부터 확인한다.

이 경로는 **21개 테이블에서 0010을 처음 추가하는 배포** 전용이다. 이후의 27개 테이블 보존 배포나 연구 코드 갱신은 해당 상태에 맞는 새 검토 계약을 사용해야 한다. 첫 배포 도구를 재실행해 장부나 데이터 상태를 초기화하지 않는다.
